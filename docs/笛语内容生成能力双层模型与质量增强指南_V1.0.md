# 笛语内容生成能力双层模型与质量增强指南 V1.0

- **形成日期：** 2026-07-25
- **文档状态：** 用户已确认的认知框架与后续质量增强依据
- **适用阶段：** 第一阶段系统完整交付后，持续优化内容质量、能力覆盖和租户差异化时使用
- **当前边界：** 本指南不改变当前里程碑范围，不代表文中所有能力已经实现、激活或验证

## 一、核心结论

笛语能否稳定生产多题材、多风格、多类型内容，主要由两个层面共同决定：

### A. 系统稳定能力

系统有没有能力理解、组织、生成和验证这类内容。

这里的“系统配置”不是几个开关或提示词，而是以下内容的合计：

- 25 类数据模型及其作用域、版本和关系；
- 领域通用知识、创作方法、媒体语法和质量规则；
- P1—P5 内容产品价值合同；
- 题材、讲法、风格、形式及系列参与方式的内容表达目录；
- 上下文编译、路由、LLM 生成、修改和平台重编译能力；
- 能够证明能力没有被后续版本改坏的必要回归。

它决定系统的能力上限。

### B. 品牌、账号与当前任务条件

系统怎样把通用能力翻译成当前品牌、当前账号和当前任务能够成立的版本。

这一层应继续分为：

1. **B1：品牌与账号长期设定**
   - 品牌战略与表达基线；
   - 品牌专属商品和经营事实；
   - 组织、发布账号和 `ContentRole`；
   - 账号五段人话画像；
   - 可复用素材、系列状态和长期制作条件。

2. **B2：本次任务输入**
   - 用户本次自然种子；
   - 本次选择的题材、讲法、风格、形式和系列方式；
   - 本次使用的商品与素材；
   - 目标平台、媒体形式和现实制作条件；
   - 当前任务需要引用的连续前情。

因此，完整关系是：

```text
A 系统稳定能力
× B1 品牌与账号长期设定
× B2 本次任务要求
→ 当前完整成品
```

其中任何一层为零，相应内容能力就不能稳定成立。

## 二、七个层级如何归入双层模型

| 原层级 | 归属 | 回答的问题 | 正确定位 |
| --- | --- | --- | --- |
| 25 类数据模型 | A | 信息能不能被正确表示、隔离和版本化 | 语义底盘，不直接产生好内容 |
| 领域通用知识与方法 | A | 系统懂不懂服装、零售和内容创作 | 提供“有料可说”和“有方法可用” |
| 品牌战略与表达基线 | B1 | 这个品牌怎样理解世界、受众和商品 | 固定内核与红线，不固定单一文风 |
| 账号五段画像 | B1 | 谁在说、凭什么说、长期观察什么 | 形成账号独特视角，不锁死题材 |
| 五轴创作方向 | A＋B2 | 系统提供哪些选择，本篇具体选什么 | 目录属于系统，本次选择属于任务 |
| P1—P5 | A | 本篇最终必须给受众什么价值 | 后台价值合同，不作为用户输入门槛 |
| LLM 与上下文编译 | A 调用 B | 怎样把全部条件编译成完整成品 | 负责生成、修改、重编译和降级 |

需要特别注意：

> **25 类数据模型能够容纳某项能力，不等于系统已经拥有并验证了这项能力。**

数据模型类似书架；知识、方法、样例和运行编译才是书架中的书。书架足够大，不代表里面已经有足够多的好书。

## 三、什么才叫“系统恒定支持”

不能因为前端出现一个选项、目录中存在一个名称或模型偶尔生成成功，就宣称系统已经稳定支持。

一项题材、风格或体裁要被认为得到稳定支持，至少需要同时满足：

```text
有明确语义定义
＋有必要知识或创作方法
＋运行时能够正确调用
＋有代表性成品证明
＋品牌和账号变化时能够正确重写
＋后续版本有最小回归保护
```

沿用现有能力证据等级：

| 等级 | 含义 | 可以怎样表述 |
| --- | --- | --- |
| `verified` | 已有方法、真实运行样例和必要回归 | 可以宣称当前范围内已验证 |
| `composable` | 可由现有能力组合，但没有专属稳定验证 | 可以尝试，不宣称恒定支持 |
| `experimental` | 模型可能完成，但稳定性和边界尚不清楚 | 只用于试验和人工判断 |
| `unsupported` | 缺知识、方法、媒体工具、权限或产品合同 | 明确缺口，不猜补能力 |

“恒定支持”不需要再建立一个新的数据库状态。它是对 `verified` 能力经过多任务、品牌反事实和版本回归后的业务判断。

## 四、品牌一致性不等于单一风格

品牌真正稳定的内容包括：

- 怎样理解目标人群；
- 长期坚持哪些判断；
- 怎样对待商品、生活和人与人的关系；
- 哪些表达绝不采用；
- 幽默、情绪、专业和商业表达最多可以走到哪里。

品牌不应被固定成：

> 只能高级、只能克制、只能温暖或只能专业。

同一个品牌可以同时生成：

- 冷静专业的商品解释；
- 温暖真诚的门店小事；
- 克制的冷幽默；
- 直接清楚的穿衣建议；
- 安静的生活记录；
- 有视觉冲击力的造型表达。

关键不是所有内容说话方式相同，而是这些变化仍然来自同一个品牌内核。

当用户选择的风格与品牌表达幅度不完全一致时，系统采用透明转译：

```text
用户选择某种表达
→ 保留用户真正想要的效果
→ 按品牌边界调整实现方式
→ 用一句人话说明发生了什么转译
→ 用户可以继续自然修改
```

不得静默替换用户选择，也不得把品牌边界变成拒绝多样表达的借口。

## 五、账号画像不等于账号只能讲一种内容

账号五段画像主要确定：

- 它代表谁、处在什么位置；
- 它在哪些内容上有真实资格；
- 它长期替哪类人观察什么问题；
- 它怎样与受众相处；
- 它在现实中通常怎样完成内容制作。

账号画像不应固定本篇的题材、风格、媒介和时长。

例如：

- 总部品控岗位账号可以做专业讲解、工作 Vlog、失败复盘、访谈和克制幽默；
- 门店人物账号可以讨论商品、穿搭、本地生活、夫妻、育儿、同事、情绪和日常琐事。

稳定的是表达位置和权威边界；变化的是本次创作方向。

## 六、品牌资料完整性采用“能力局部门”，不采用“全局完整度”

品牌无需完成一套巨型资料库后才能开始使用系统。

正确规则是：

> **缺少什么，只限制真正依赖它的主张或任务；其他能够成立的内容继续生产。**

示例：

| 当前缺口 | 影响 | 不应影响 |
| --- | --- | --- |
| 没有具体商品事实 | 商品承重的 P1/P2/P5 收窄或暂停 | P3 人格内容、非商品 P4 |
| 没有真实评论 | 不能冒充顾客反馈 | 主动发现关系命题 |
| 没有演员或复杂场地 | 改成一人手机、持衣、旁白或图卡 | 完整成品交付 |
| 没有价格或库存 | 不写价格、库存和促销判断 | 商品已有可观察事实的内容 |
| 账号画像较轻 | 使用当前最小版本并保持边界 | 不要求一次填完全国账号矩阵 |

禁止建立一个“品牌资料完整度不足，所以整个租户不能生产”的总闸门。

## 七、后续发现质量问题时，先判断问题属于哪一层

系统完整交付后，每个内容质量问题先按以下顺序诊断。

### 1. A 层问题：系统能力缺口

典型表现：

- 多个品牌、多个账号都生成同一种结构；
- 某种体裁只有名称，没有真正方法；
- P5 经常被路由成 P1；
- 平台版本只换标题和标签；
- 用户明确修改后，系统反复忽略同类要求；
- 相同能力在版本升级后普遍退化。

处理方式：

- 补领域通用方法或媒体能力；
- 修正共享编译、路由或上下文合同；
- 增加一个能真实失败的最小回归；
- 不为单一样例增加专用提示词或关键词补丁。

### 2. B1 层问题：品牌或账号定义不足

典型表现：

- 同一系统对其他品牌正常，只有某品牌持续失真；
- 品牌所有内容被“高级、温暖、克制”等空洞形容词压平；
- 总部和门店只替换账号名称，观察位置没有变化；
- 账号不断说超出自身岗位资格的话；
- 品牌边界过窄，用户选择的风格频繁被取消。

处理方式：

- 修订品牌战略基线或账号五段画像；
- 补充正例、反例和表达幅度；
- 将特殊需求先保存为该租户专属预设；
- 不自动污染领域通用规则。

### 3. B2 层问题：本次任务条件不足或表达不清

典型表现：

- 用户没有指定不可替代商品；
- 本次平台、形式或制作条件不清楚；
- 用户想延续系列但未选定前情；
- 某项要求只适用于本篇，却被误当成长期品牌规则。

处理方式：

- 优先根据已有上下文主动完成；
- 能省略、替代或降级时直接完成；
- 只有结果无法成立时才合并追问一次；
- 本次任务信息默认不进入长期记忆。

## 八、系统全部交付后的质量增强方法

后续质量增强采用一条最小闭环，不提前建设重型评测平台。

### 第一步：收集真实问题

来源只包括：

- 用户自然修改；
- 用户明确提出但系统不能满足的题材、风格或形式；
- 实际生成中的稳定失败；
- 不同账号、品牌和平台的反事实差异不足；
- 用户自愿提供的发布反馈和评论问题。

单篇高播放、一次采用或模型自评不能自动证明新能力。

### 第二步：归入 A、B1 或 B2

先确定是系统通用能力、品牌/账号定义，还是本次输入问题，避免所有问题都通过修改 Prompt 解决。

### 第三步：选择最小补全方式

| 缺口 | 优先补法 |
| --- | --- |
| 目录已有、能力能组合 | 增加别名或组合预设 |
| 风格定义不精确 | 补风格档案、正例和反例 |
| 缺创作机制 | 补领域通用方法卡和最小样例 |
| 缺媒体制作能力 | 补媒体方法；确需工具时再开发 |
| 品牌特有表达 | 建租户专属预设 |
| 缺商品或经营事实 | 只补当前任务必要品牌资料 |
| 超出产品边界 | 明确不纳入或另行立项 |

### 第四步：做代表性验证

不运行“20 × 55 × 44 × 平台 × 账号”的笛卡尔积。

只选择能代表真实风险的少量组合，验证：

- 同一品牌不同风格仍然属于同一品牌；
- 同一题目换账号后内容实质重写；
- 同一事实换平台后结构实质变化；
- 换品牌、商品或区域后承重内容相应变化；
- 用户修改形成 V2，V1 保留；
- 商品、人物、经历和经营事实不被创造；
- 缺资源时能省略、替代或降级。

### 第五步：决定作用域

单个品牌提出的特殊能力先进入该品牌专属范围。

只有同时满足以下条件，才允许升级为领域通用能力：

- 不含品牌私有信息；
- 多个任务可以复用；
- 不依赖单一租户的具体事实；
- 通过品牌和账号反事实；
- 有最小回归证明。

## 九、内容质量长期维护的三条护城河

### 护城河一：同一品牌内的多元表达

品牌调性稳定，但题材、讲法、风格、形式和系列方式足够丰富，不退化成一套品牌模板。

### 护城河二：不同品牌和账号的实质差异

更换品牌、账号、商品或地域后，内容的观察位置、判断、结构和表达必须实质变化，而不是只换名称。

### 护城河三：内容市场的真实竞争基础

每篇内容至少具备：

- 对真实受众有意义的问题或回报；
- 明确判断、认知增量、关系价值或视觉价值；
- 真人能够自然说出口；
- 当前制作条件能够完成；
- 平台版本不是机械搬运；
- 没有模板化宣讲、无来源经历和通用 AI 腔。

这里验证的是竞争基础，不承诺播放量、爆款率、排名、GMV 或销售结果。

## 十、明确禁止的增强方式

- 不因增加风格和题材而新增大量核心本体类；
- 不建设品牌类型到固定文风的静态矩阵；
- 不要求所有租户一次填完品牌、商品、账号和素材；
- 不把账号画像变成知识访问权限；
- 不把某个租户的一次需求自动升级成全局能力；
- 不运行全组合穷举测试；
- 不建设迎合平台黑箱的流量预测器；
- 不建设所谓“AI 检测对抗系统”；
- 不用关键词黑名单和样例特判掩盖共享编译问题；
- 不以目录数量、测试数量和模型自评分代替用户可见成品；
- 不因后续优化需要而阻塞当前已经能够成立的软件交付。

## 十一、如何使用本指南

本指南是系统第一阶段完整交付后的质量增强依据，不是当前施工范围扩张指令。

后续每次增强只需回答四个问题：

1. 当前失败属于 A、B1 还是 B2？
2. 它影响哪个真实用户结果？
3. 最小补全是知识、方法、品牌/账号定义，还是任务输入？
4. 用哪一个代表性成品和反证证明修复成立？

回答不清楚时，不新增数据模型、流程、评测器或平台。

## 十二、最终判断

> **A 决定笛语会多少；B1 决定当前品牌和账号怎样使用这些能力；B2 决定本篇具体调用哪一部分。**
>
> **25 类数据模型负责承载扩展，领域库负责提供能力，品牌基线负责保持灵魂，账号画像负责建立视角，五轴方向负责开放创作空间，P1—P5负责守住受众价值，LLM与上下文编译负责把这些条件变成完整成品。**

系统后续内容质量增强的重点，不是继续增加字段，而是持续提高这些层级之间的正确编译、真实差异和稳定交付能力。
