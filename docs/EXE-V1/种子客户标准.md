# 种子客户（付费设计伙伴）选择标准

> 口径来源：D-COMM-05（最低制作包为签约前门槛）、D-COMM-05b（与 B6 复用同批人）、
> D-COMM-06（收费线下）、D-COMM-09（有界陪跑 supersession）。
> 本文只定义**怎么选人**与**登记什么**；真实客户的建租户与素材入库属本包收口后的运营动作。

---

## 一、硬性条件（不满足即不入选，无例外）

| # | 条件 | 为什么 |
|---|---|---|
| H1 | **真实岗位、真实在做内容** | 对象必须是每周真的要发内容的人（店长、店员、内容负责人），不是替公司来"评估工具"的人。评估者给不出真实约束 |
| H2 | **能到场陪跑** | 当前只做有陪同交付。约不到人、只能远程自己试的，不符合本阶段边界 |
| H3 | **有可用素材** | 至少能提供本店真实商品信息与图片。没有素材，产品只能空转，测出来的都是假问题 |
| H4 | **接受"不自助、不自动发布"** | 当前不开放无陪同登录，也不代发。接受不了的，等 B6（EXE-09）放行后再谈 |
| H5 | **同意留痕** | 同意会话过程、反馈与决策被记录用于产品改进（不含其顾客个人信息） |
| H6 | **线下付费与合同** | 费用、周期、账号数、服务范围走线下合同/报价单。产品内没有购买入口，也不会有 |

## 二、优先级（同等条件下优先选谁）

| 优先 | 特征 | 理由 |
|---|---|---|
| P1 | **服饰零售、有实体门店** | 与当前已建成的领域知识、商品与陈列能力吻合，最能测出真实差距 |
| P2 | **一个品牌下有 2–3 个不同定位的号** | 能验证"不同账号写出不同内容"——这正是本轮价值引擎的核心主张 |
| P3 | **决策链短**（老板本人或直接汇报老板） | 反馈能当天转成决策，不被中间层稀释 |
| P4 | **愿意说难听话** | 只会夸的样本对产品无价值 |

## 三、排除项（出现即不选）

- 只想要"便宜的写手替代品"，不关心内容是否属于自己品牌；
- 要求**立刻自助使用**或**自动发布**；
- 无法提供真实商品信息，只能给概念/PPT；
- 所属行业与服饰零售差距过大（本阶段领域知识覆盖不到，测出来的问题不可归因）；
- 需要产品侧计费、套餐、席位等功能才肯签（D-COMM-06 明确不做）。

## 四、与 B6 可用性门的关系（D-COMM-05b）

- 本阶段陪跑对象与 **B6（EXE-09）可用性门的测试用户复用同一批人**，不重复招募；
- 但**两轮记录分别留存**：陪跑轮 = 有 founder 在场；B6 轮 = **无陪同自助**；
- **本包的陪跑记录不能用来声称 B6 通过**。B6 必须是真实用户在没人帮的情况下完成，
  这条不因本包的有界 supersession 而放宽。

## 五、登记表（每位种子客户签约前必须填齐）

> 存放位置：**运营侧私有记录**，不进仓库。仓库内只保留本模板与聚合计数。

| 字段 | 说明 | 必填 |
|---|---|---|
| 客户主体 | 公司/门店主体名称 | ✅ |
| 品牌名 | 实际运营的品牌 | ✅ |
| 指名租户 | 系统内 tenant，一客户一租户 | ✅ |
| 指名逻辑账号 | 本轮开放的发布账号（建议 ≤3） | ✅ |
| 指名操作者 | 姓名 + 岗位 + 联系方式，**只有登记的人能操作** | ✅ |
| 陪跑周期 | 起止日期 | ✅ |
| 会话数上限 | 本周期内陪跑会话次数上限 | ✅ |
| 生成条数上限 | 本周期内生成内容条数上限 | ✅ |
| 模型费用上限 | 超出即停，转报告 | ✅ |
| 合同/报价单编号 | 线下财务流程凭证 | ✅ |
| 素材交付方式 | 谁在什么时候提供什么素材 | ✅ |
| 边界确认签字 | 已阅读并接受 [已知边界卡.md](已知边界卡.md) | ✅ |
| 事故联系人 | 出问题时找谁，见 [事故回滚协议.md](事故回滚协议.md) | ✅ |

## 六、禁止条款（写进合同）

陪跑期内，产品侧**不做**以下事情，需在合同或交付说明中明确告知：

- 不自动发布到任何平台；
- 不开放无陪同自助登录；
- 不新增登记表以外的用户；
- 不在陪跑过程中修改画像 / 品牌资料 / 权限（需要改时走单独授权流程）；
- 不承诺任何未上线能力的时间表。
