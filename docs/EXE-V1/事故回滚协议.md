# 事故联系与回滚协议

> 适用：陪跑交付期内出现异常时，谁在多久内做什么。
> 配套：技术动作全部引用 [部署runbook.md](部署runbook.md) §2，本文不重复命令细节。

---

## 一、联系路径

| 角色 | 职责 | 触达方式 |
|---|---|---|
| **使用者 / 客户侧联系人** | 发现异常，立即停止使用并通知 founder | 登记表中的联系方式 |
| **founder** | 唯一裁决人：判断严重度、决定是否回滚、对客户说明 | 客户侧只联系 founder，不直接联系执行侧 |
| **执行侧（运维）** | 按 founder 指令执行回滚 / 取证；发现技术异常主动上报 founder | founder 直接触达 |

> **单一入口原则**：客户侧只找 founder。执行侧不直接对客户承诺任何事。

## 二、严重度分级与响应时限

| 级别 | 定义 | 立即动作 | 时限 |
|---|---|---|---|
| **P0** | 跨租户可见 / 疑似数据损坏 / 密钥或凭据泄漏 | **立即停写** + 保留现场 + 回滚运行时 + 通知 founder | 发现即刻 |
| **P1** | 服务不可用、登录不能、生成全部失败 | 回滚运行时 → 恢复后复盘 | 30 分钟内 |
| **P2** | 生成内容出现事实性错误（编造商品/价格/顾客经历） | 停止本条使用，记台账；**同类连续出现 ≥2 条则升 P1** | 当次会话内 |
| **P3** | 体验问题、个别失败可重试成功 | 记台账，不回滚 | 当天 |

## 三、回滚触发条款（出现即回滚，不需再请示）

引用 D-COMM-09 与本包不可豁免刹车：

1. **租户隔离破裂** —— 任一使用者看到不属于本租户的数据；
2. **事实性错误成规模** —— 无来源的商品/价格/工艺断言或编造的人物门店经历；
3. **疑似数据损坏** —— 快照 digest 校验失败、历史版本被改写、append-only 表出现改写；
4. **冒烟红** —— 部署后冻结路由矩阵任一行与预期不符；
5. **安全退化** —— 未授权可达受保护入口、会话串用、密钥泄漏迹象。

### 关键区分：回代码，不回数据

出现 P0「疑似数据损坏」时：

- ✅ **回滚运行时代码**（止血）；
- ✅ **停写、保留现场、取证**；
- ❌ **不回滚数据**。数据处置属独立裁决，由 founder 单独决定。

> 理由：数据回滚会同时抹掉证据。先止血、先保留，再判断。

## 四、回滚执行

技术动作见 [部署runbook.md](部署runbook.md) §2「回滚命令」。要点：

- 回滚目标 = **部署前锚点 SHA + 其 image digest**，两者在每次部署前已冻结进私有证据根；
- `rollback.sh` 会自动把公网路由切回，健康检查不过则公网路由保持不动；
- 新旧都起不来时用 `rollback.sh maintenance` 挂维护页（数据与镜像全保留）。

**回滚前必须先做的一件事**：把现场证据抓下来（容器日志、相关 task 的
`inspect_task_value.py` 输出、异常截图），存进私有证据根。回滚会覆盖运行状态。

## 五、对客户的说明口径

| 场景 | 说法 |
|---|---|
| P0/P1 回滚 | "我们发现了一个问题，已经把系统退回到上一个稳定版本。你之前的内容都在。我会在 <具体时间> 前给你说明。" |
| P2 事实错误 | "这条它编了，我们记下来了。这也是现在必须人工过一遍事实的原因。" |
| 追问什么时候修好 | "我会在复盘后给你确切答复。" —— **不当场给时间表** |

**禁止**：把回滚说成"例行维护"；承诺未经复盘的修复时间；向客户解释内部技术细节。

## 六、事后复盘（每次 P0/P1 必做，48 小时内）

| 项 | 要求 |
|---|---|
| 发生了什么 | 时间线，含发现时刻与回滚时刻 |
| 触发的是哪条条款 | 对应上文第三节编号 |
| 影响面 | 哪些租户/账号/内容受影响，是否有数据变更 |
| 根因 | 查明为止；未查明就写"未查明"，不允许猜测性结论 |
| 处置 | 改什么 / 不改及理由（同台账口径） |
| 是否需改本协议 | 是 → 当轮改 |

复盘记录存放运营侧私有记录；仓库内只保留聚合结论与对本协议的修订。
