以真源为准。

## 生成与核对

在仓库根目录运行：

```bash
python3 docs/能力资产台账/export_readable_projections.py --write
python3 docs/能力资产台账/export_readable_projections.py
```

第一条只覆盖本目录的两份 CSV，不修改任何 JSON/JSONL 真源；第二条不写文件，只验证
投影内容、来源摘要、243/119 行数、ID 唯一性、41 条运行激活和 6 条直接资产关联。真源
摘要变化时脚本会停止，要求先人工理解变更，不会静默刷新总账。

UI-03 只补齐了 5 个既有实验项的唯一后续去向，使 45 个非稳定 ID 对账为
`F10 41 / F03 1 / F06 1 / F07 1 / F08 1`；能力状态、精简目录可见性和运行激活集合
均未改变。正式 React 内容主链动态消费精简目录中的 24 项，连续系列完整旅程仍归 UI-04；
这项消费者接入没有新增运行资产激活。

## 阅读边界

以下状态不能互相替换：

`候选登记` ≠ `运行激活` ≠ `某次任务实际调用` ≠ `已验证能力` ≠ `真实租户采用`

同样，243 条系统资产、119 个内容表达目录位置、25 类语义模型、平台媒体目标、品牌候选
资料和 VI 文件是不同资产家族，不能相加后宣称“系统共有多少项能力”。
