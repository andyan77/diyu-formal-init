## 候选结果

在不改 Writer、模型和 DeliveryCompiler 职责的前提下，使服务端能够按来源、unit contract、
可信主体绑定和 exact grammatical evidence，对一般建议、抽象因果、服务端假设、真人事实与
机构主张作一致裁决。

UI-12 当前没有 `ACTIVE`、`READY` 或实现候选 SHA。UI-11 仍为 `BLOCKED`。

## 最小代码范围

仅在主控接受 ADR 后考虑：

1. `src/shared/review_evidence.py`
   - 生成带服务端 sidecar 的 clause context；
   - 保留 V1 legacy；
   - 新增 V2 的唯一字段 `grammatical_marker_spans`；
   - 按 SDR-001—SDR-037 实施 allow/reject/insufficient/structural 四类结果。
2. `src/shared/creative_kernel.py`
   - 若现有 program/unit 映射不足，仅增加确定性的 contract 派生函数；
   - 不改变 Writer 的 `unit_id+text` 输出；
   - 不建立第二套 DSL，不回填旧快照。
3. `src/tool/llm_gateway/deepseek.py`
   - Reviewer schema 只增加 grammatical exact spans；
   - 不修改 Writer 请求、模型、参数或重试；
   - 不让 Reviewer 返回 type、binding 或 pass/fail。
4. 现有 pytest/Golden
   - 复用当前平台增加 SDR 直接消费者；
   - 离线重放 EVD-014—020；
   - 增加 `insufficient_evidence` 非 Writer-repair 反证。

预期不需要修改：

- ContentService 事务边界；
- CreationIntentGate、CreativePlanV2、NarrativeFrame；
- Writer 输入输出；
- DeliveryCompilerV1；
- repository、数据库、迁移；
- OpenAPI、前端、部署配置；
- legacy 快照读取。

## 必须先绿的确定性消费者

1. server wrapper 自身只做结构校验；
2. Writer 伪造同文 wrapper 不获资格；
3. frozen user/brand/product fact 逐字通过且不可改；
4. 泛指 recommendation action 通过；
5. 泛指 abstract cause/result 通过；
6. abstract 的 action+result+location 微事件拒绝；
7. hypothesis 的 generic/fictional action 通过；
8. hypothesis/current/protected binding 拒绝；
9. institutional predicate 无 frozen brand fact 拒绝；
10. 四句语态反证分别为 allow/reject/allow/reject；
11. 零标记歧义句为 `insufficient_evidence`；
12. H1/D1 单 body program 使用 Frame 冻结 contract，不再误报 `kernel_program_drift`；
13. Reviewer coverage/span/uncertain 不进入 Writer 修复；
14. narrative 人物不污染 production resources；
15. compiler 不新增未审语义；
16. G4/G7 frozen fact、Frame、program、source、compiler version 不变量保留；
17. V1/legacy 快照继续可读、可修改、可复制和导出。

## 证据与 mutation 候选

至少证明：

- 删除 clause source 后 wrapper 用例变红；
- 让 Writer 同文获得 wrapper 资格后伪造用例变红；
- 删除 grammatical marker 对账后四句反例变红；
- 恢复“任一 action/cause/result 即事件”后泛指建议/因果变红；
- 放松 protected/current subject 后机构/真人反证变红；
- 把 `insufficient_evidence` 送 Writer 修复后修复纪律用例变红；
- narrative role 进入 resource refs 后资源闭世界用例变红。

## 后续真实验证候选顺序

这部分只有新执行包明确授权后才能运行：

1. 当前 Reviewer A/B/C 与 grammatical 四句资格样本；
2. 同一 SHA 的 G3 一次初稿、最多一次合法 affected-unit 修复；
3. G3 通过后才运行 G4、D1；
4. 再决定完整本地门、两份有界审查、push、CI 与生产。

不得使用本次诊断的离线重放冒充真实 Reviewer 或生产证明。

## 停止线候选

- 只能靠新增中文题材/人物/失败句词表；
- Reviewer 重新获得类型或 pass/fail 权；
- V2 仍无法区分四句反例；
- server wrapper 与 Writer 同文字仍拥有相同资格；
- `insufficient_evidence` 只能靠 Writer 重写掩盖；
- 需要改 Writer 策略、模型或 DeliveryCompiler 才能继续；
- legacy、事实、资源、RLS 或事务边界受损。

## 明确排除

模型比较、更换供应商、fallback、第二 Reviewer、随机重跑、第二修复、数据库变化、新平台、
前端扩张、知识激活、目录扩张、自动发布和生产操作均不在候选范围。

## 当前唯一动作

主控审阅并裁决 SDR 决策表与 ADR 候选。未确认前不得把本文改名为执行包，也不得开始 UI-12。
