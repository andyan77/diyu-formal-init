## 1. 根因与取代关系

UI-08 已证明当前与唯一候选 Writer 在同时承担叙事文字、scene、资源、动作、声音和制作提示时
均为 `0/3`。该结果没有授权第三模型或继续补 Prompt。UI-09 只修正 Writer 单角色职责：
创意文字先形成单一可审内核，制作条件随后由服务端确定性编译。

UI-08 的 Gate、计划、Frame、事实／约束分离和观察类型继续有效；其 `BLOCKED`、两个
Writer `0/3`、Reviewer 未验证、未 push/CI/部署与证据完整保留。

## 2. 产品责任

用户只需提供商品款号、生活片段、流水账、感悟或抱怨，可选题材／风格／形式控制；系统负责
选择主线、受众回报、平台表达和完整交付。只有缺少不可替代真实事实才追问一次。未提供的真人、
商品或品牌事实不得补造，默认直接交付完整平台 V1，不交付问卷、选题或提纲。

## 3. 唯一运行链

```text
CreationIntentGate
→ CreativePlanV2 / NarrativeFrame
→ CreativeKernelV1 Writer
→ 独立 Reviewer
→ 最多一次受影响可写 unit 修复并完整复审
→ DeliveryCompilerV1
→ 原子保存完整 V1
```

Writer 只返回 `{"units":[{"unit_id":"服务端既定 ID","text":"完整可见文字"}]}`。服务端冻结
unit id、purpose、允许观察类型、fact refs、constraint refs 与可见顺序；事实 unit 由服务端
逐字插入且不可修。额外、遗漏、重复、漂移 ID 或任何制作字段均失败。

## 4. 事实、输入与单元边界

- 真人原文、精确商品事实、精确品牌机构主张只由服务端逐字插入。
- Writer 只读 topic 精确跨度、必要事实、P1—P5 价值、平台／形式、去标识语气节奏、修改要求
  和 unit skeleton；不读不必要的品牌／组织／账号名称、长基线、资源表或 Reviewer 历史。
- 单元允许 `frozen_fact`、`abstract_observation`、`hypothetical_example`、
  `disclosed_dramatization`、`recommendation`。微场景只能进入已披露假设／演绎单元。
- 无精确品牌事实时不强制 P3 `brand_account_link`；账号观察、受众回报和当前文章视角即可。

## 5. DeliveryCompilerV1

编译器只消费已审内核、平台／媒体形式、登记生产条件、合法资源及已激活制作方法，确定性生成
现有 `GeneratedArtifact` 与 `ProductionBundle`。它不得增加现实事实、机构主张、人物、场地、
家具、道具或环境声；商品只有存在 `resource:product:*` 才能入镜。D1 无多演员／家庭现场时
编译为文字对话卡、旁白或一人分段表达，不声称存在第二演员或现实家庭场景。

每个最终可见字段必须追到已审 unit、服务端事实块或版本化中性编译短语；资源必须来自冻结集合。
新任务快照记录 `creative_kernel_v1`、`delivery_compiler_version`、
`reviewed_kernel_digest` 与 visible provenance。不新增表、迁移或历史回填；旧任务按快照
版本继续读取、修改、复制、导出、系列与跨平台改编，不作为新任务失败 fallback。

## 6. Reviewer 与修复

Reviewer 先以三条冻结样本验证 `abstract_principle/situated_event/institutional_assertion`
资格，再审 CreativeKernel 全 unit 精确跨度和完整覆盖。漏 unit、假／部分跨度或 uncertain
均失败。制作资源由服务端闭世界验证，不重复审查编译器复制的正文。

每个成品最多一次受影响可写 unit 修复并完整复审；事实、Frame、Plan、资源与编译器版本不可
修。第二次失败立即停止。两份人工审查若由同一执行端完成，只称不同范围的有界审查。

## 7. 确定性与真实模型门

在现有 pytest/Golden 增加 Writer 禁止制作字段、unit 闭世界、事实不可变、机构主张、
未披露微事件、抽象原则、D1 段级披露、编译器文字／资源闭世界、G7 不变量、非固定成稿与
legacy 兼容反证；对 Gate、事实、制作字段、资源和 G7 做 mutation proof。

确定性门通过后，只用 `deepseek-v4-flash`、`temperature=0`、`max_retries=0`，不连接业务
仓储，对 G3/G4/D1 各执行一次；每卡最多一次受影响 unit 修复与完整复审。仍失败即
`BLOCKED`，不比较模型、不重跑、不加词表或第三 Writer 策略。

## 8. 完成门与停止线

三卡通过后，才执行同 SHA 本地 G1—G7/H1/D1、完整标题／正文／辅助内容／制作建议、失败
原子性、RLS／跨作用域、历史／系列／平台父子、DM01、AIGC 与资产 `41/243/25/119`，再串行
执行 Makefile 真源、前端 lint/typecheck/interaction/build 和两份有界审查。

全部通过后才一次 push 线性历史并等待唯一 CI。CI 绿色后才以 `umask 077` 新建备份，验证
`0700/0600`、checksum、隔离恢复、RLS、对象恢复，再同 SHA 部署、连续生产验收、往返回退
和精确清理。任何生产语义失败立即停止、清理、回退并置 `BLOCKED`，不形成第二生产候选。

结构或模型阶段失败、第二修复、随机重跑、固定成稿、题材／人物／句型词表、第三模型、
`deepseek-v4-pro`、fallback、迁移、新平台或降低事实／隔离边界，均命中停止线。
