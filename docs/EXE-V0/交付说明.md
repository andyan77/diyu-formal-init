## 一、这个包换掉了什么

改之前，`audience_payoff`（写给 Writer 的「给读者的回报」）是按产品类型查的一张静态表：六个题材共六句固定文案，
签名只吃 `primary_product` 和 `topic_origin`，校验只查非空，所以永远绿。这句空话坐在 Writer prompt 权重最高的位置上。

改之后，这句话由服务端**确定性组装**：零 LLM、同输入同输出，从「画像哪几段有内容 / 题材 / 内容产品 /
是否有冻结商品依据 / 是否有有效系列」这些**信号**里选一条版本化模板，拼出这一篇自己的回报句；
组装不成就退回静态句，但把「降级了、为什么降级」明明白白记下来，不静默冒充成功。

真实性防线（「不能是什么」）一行未动。Writer 读合同的那一行也一行未动。

## 二、承重设计与它守住的边界

| 设计 | 为什么这样做 |
| --- | --- |
| `TaskValueAssemblyV1` 独立版本化对象（`src/shared/task_value_assembly.py`），随任务快照存 `content_context_snapshot`，单独带 digest | 不原地扩写 `publication-contract-v3` 结构，历史 digest 字节兼容红线不碰；jsonb expand-only，**零 migration** |
| `PublicationContractV3.audience_payoff` 仍是 Writer 唯一消费值 | 组装值 == 冻结合同值 == Writer 收到值，三处相等有断言 |
| 组装器（`src/brain/payoff_assembly.py`）只吃信号，不吃原文 | 回报句只由版本化审核模板 + 白名单语义片段拼成；画像五段原文、seed 原文、商品事实值一律不进句子、不进 trace、不进仓库 |
| `assembly_trace` 是精确类型合同 | 只有枚举字段名 + template_id + ruleset digest + 两个布尔；零原文、零内部 segment id、零 PII |
| `product_contract_job()` 把 `central_job` 语义冻结为五类产品不变量 | 本包换的是「读者拿到什么」，不是「产品欠什么」；组装前后再算一次并断言相等 |

### 可产路径与保留路径

`brand_relevance_path` 七枚举出自 ADR-013 §4（品牌立场 / 目标人群关系 / 商品与专业认知 / 组织人物 /
本地服务信任 / 品牌视觉 / 既有系列）。本包按 v1.1 收窄：

- `V0_PRODUCIBLE`：`product_expertise`（仅 `product_decision_basis.supporting_fact_refs` 非空触发）、
  `existing_series`（仅有效 `series_delta` 触发）、`audience_relationship`、`brand_stance`。
- `V0_RESERVED`：`brand_visual`、`local_trust`、`organization_people` —— 一律不产。
- 降级时 `brand_relevance_path = null`、`payoff_degradation_reason` 必填；**不为凑枚举伪造路径**。

### 安全构造（当场可反证）

- 生活叙事 / 本地回应即使旁边冻着商品依据，也不会被改写成商品题材 → `safety_gate_rejected` 降级，有测试。
- 规范化后等于任何一句静态默认句 → 硬门拒绝 → `invalid_assembly` 降级，有测试。
- 静态默认句集合由 `product_brief()` **派生**得到，不是抄进代码的，所以静态表改了这道门自动跟着走。

## 四、L1 自主决策清单

1. **环境对齐 CI 的 Python 3.10**（见上）。理由：唯一权威 CI 即 3.10；不动仓库文件。
2. **worktree 目录名用 `exev0`，分支名仍是 `exe-v0-value-engine`**。理由：本地测试用的 PostgreSQL
   Unix socket 路径有 107 字节硬上限，长目录名会让 `pg_ctl` 起不来。仅目录命名，无仓库语义。
3. **没有改 `src/shared/publication_contract.py`**。§1 给的是「仅确需时」，实测不需要：静态默认句用
   `product_brief()` 派生，`central_job` 用 `product_contract_job()` 转发。该文件与基线 sha256 一致。
4. **快照挂载点选在 `content_service.py` 的两个调用处**，不是 `snapshot_document()` 本体。理由：
   `snapshot_document()` 在 `src/brain/content_expression.py`，**不在本包 allowlist**；在调用处做
   expand-only 合并，语义等价且不越界。
5. **`used_profile_fields` 只记「真正撑起本次路径」的字段**（商品/系列路径下为空），不记「所有非空字段」。
   理由：后者会把没参与决策的字段写成证据，属于假证。代价是「六题材各可指回画像字段」这条样本目标，
   在商品/系列路径行上指回的是冻结依据而非画像字段 —— 对照报告如实分列，不含糊。
6. **函数预算棘轮当场拦下三处增长**（`_new_publication_contract` 186→203、`create_from_weak_seed`
   295→298、`recompile_task` 241→244）。按「新逻辑抽 ≤60 行函数、基线超限函数不得增长」重构，抽出
   `_explicit_user_controls` / `_frozen_task_value` / `_frozen_publication_spans` /
   `_recarried_publication_contract` / `_snapshot_with_task_value` 五个函数，三处最终均**低于**基线行数。
7. **`revise`（V1→V2 修订）无需改代码**：它本来就从快照读回冻结的 `PublicationContractV3`，
   所以改画像后再修订必然沿用原冻结值。`recompile_task`（跨平台改编）会新建任务快照，故显式把冻结的
   assembly **原样带走**，不重新组装。**历史快照零回填零覆盖**：没有这两个键的旧任务读出 `None`。
8. **降级原因判定顺序**：`invalid_assembly` > `safety_gate_rejected` > `unsupported_relevance_path` >
   `missing_profile_signal`。四个原因各有反证测试。
9. **「六个题材」的口径**：静态表实际区分的六种 `(content_product, topic_origin)` 组合
   （四类产品各一 + `brand_life_narrative` 按题材来源分两种）。

  > **P0 现场更新（施工期间发生，本分支未包含该文件）**：授权基线 `c37ae785` 之后，治理分支
  > `origin/claude/brand-knowledge-pilot-review-8a3105` 前进了一个 commit `a884a10`

  > `docs/EXE-V0/P0-裁决摘要.md`。该裁决与本包交付一致，不改变本包任何结论：
