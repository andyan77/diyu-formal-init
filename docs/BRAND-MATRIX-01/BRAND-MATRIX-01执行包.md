## 三、冻结的八条业务剧本

1. 总部建立品牌母 IP、商品事实、J 判断和 G 规则；
2. 华东区域维护气候、节庆、商圈及区域资料；
3. 杭州门店维护地址、营业时间、服务、设施和本地资料；
4. 成都门店上传与总部事实冲突的普通资料，证明不能污染正式事实；
5. 同一 SKU 分别由总部、华东、杭州、成都建立四个独立任务，证明同一事实、不同节点表达；
6. 同一种子分别使用品牌官方号、店主/顾问号和人物账号建立独立任务，证明操作人、账号、
   角色和视角分离；
7. 导入 `AMD-2026-0808-01`，证明旧任务继续读取 v1、新任务采用 v2；方言条款升级作为
   真实版本案例；
8. 门店反馈进入观察层，证明不会自动升级成 BrandFact、ProductFact 或 G 规则。

**八个异常样本**：过期资料；门店错误成分；同字段正式事实冲突；过期区域活动；跨门店读取；
两名用户共同操作一个逻辑账号；私人经历单次授权；知识更新前后两版任务。

每条剧本逐篇二元判定，不允许用平均分掩盖单条失败。

## 四、最终状态机与停止条件

```text
S0 基线收账
  → Gate A 素材合同
  → Gate B 账号语义与品牌关联
  → Gate C 作用域、时效与授权治理
  → Gate D 隔离全量预演（含媒体母版完成）
  → 冻结唯一候选 SHA/镜像
  → Gate E 密封盲测
  → 生产部署与正式导入
  → REVIEW
  → 主控终审 CLOSED
```

普通代码错误、测试失败、字段遗漏由执行侧在当前 Gate 内自主修复，不得反复向 founder
索取裁决。**只有四类情形允许停止**：业务目标改变；需要降低隔离/安全；超过 300 次模型调用；
无法安全部署回退。

### Prompt 4：Gate C · 组织作用域、生命周期、冲突与人物授权

### Prompt 6：Gate E · 密封盲测、唯一 CI、生产部署与正式建库

**密封盲测机制**：由未参与实现的一方制作 20 张盲测卡和固定评分表；明文不得进入仓库、
工作树或执行窗口；对外只登记卡数、覆盖矩阵、文件 digest、创建者、创建时间、加密包
digest；解密口令只由主控持有；候选 SHA、Prompt、模型、规则、数据 manifest 和镜像全部
冻结后才开封；当前公开的 15 卡继续作为普通回归，不计入 20 卡盲测；开封后禁止根据具体
措辞修改 Prompt、规则、fixture 或 oracle；本轮失败则该 20 卡立即降级为公开回归集，
下一候选必须换全新密封集。

盲测硬门：machine hard 20/20；structure 20/20；高风险事实边界 20/20；first-draft usable
≥17/20；任意硬边界失败整门失败；17/20 只用于产品首稿质量，绝不放宽事实、权限或资源安全。

**Gate E 执行顺序**：冻结唯一运行 SHA、配置 digest、数据 manifest 和镜像 → 完整本地门和
唯一权威 CI → 同一镜像+隔离恢复库开封运行 20 张盲测卡 → 盲测通过后生产前备份与隔离恢复 →
部署同一镜像（不在部署端重建）→ 生产复用 Gate D 验证过的导入器（dry-run→batch digest 与
对象差分→与冻结 manifest 对账→确认→正式导入→逐表盘点）→ 创建十个正式逻辑账号、画像、
平台目标和权限 → 迁移必要资格并归档旧账号（前端激活列表严格为十个新账号）→ 正式导入
`AMD-2026-0808-01` v2 → 导入并绑定 26 个母版（原始视频不进入生产素材选择）→ 生产完成
八剧本端到端浏览器验收 → 上一健康镜像往返回退（不降级数据库）→ 精确清理 synthetic、
临时 token、会话、容器、浏览器和凭据投影 → 进入 `REVIEW`，不得自行 `CLOSED`。

### 主控终审与 CLOSED（控制动作）

只读取 Gate E 最终 SHA 和证据，不改代码、不重跑模型、不部署。最多两份正式独立审查
（产品/账号差异/八剧本；工程/安全/隔离/证据）。两审均 PASS 后更新 MILESTONE.md、本执行包、
使用说明、路线图和项目记忆（文档提交 `[skip ci]`），状态置 `CLOSED`。任一审查失败，只能
在原 Gate 内按共享根因做一次合并返工；不得创建 successor、不得逐卡补 Prompt、不得无限循环。
