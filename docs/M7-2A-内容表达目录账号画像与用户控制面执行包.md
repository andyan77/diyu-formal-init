## 一、本里程碑交付什么

让用户在保持自然语言主入口的前提下，获得一个**最小内容控制面**：

1. 可选地控制本次的题材、讲法、风格、形式和连续方式；
2. 看见自己的原始选择在品牌边界下如何被透明转译；
3. 使用可版本化、可追溯的发布账号五段表达画像；
4. 自己控制私人创作偏好（查看／修改／关闭／恢复／删除／本次完全不读不写）；
5. 显式选择本次允许使用的文字素材或原媒体的人工说明；
6. 获得账号冷启动的内容机会与一份可修改的轻量计划；
7. 提交当前系统未满足的创作需求。

**不是**内容市场质量试点、不是 M6-3 七卡复验、不是真实连续系列、不是平台流量/SEO/趋势验证，
也不建设第二套生成器、人格系统、评测平台或审批流程。

## 二、五轴与目录真源

系统内部固定五轴：`topic` 题材、`mechanism` 讲法、`style` 风格、`form` 形式、`continuity` 连续。

目录真源是**版本化仓库数据**，不建数据库目录后台：

| 文件 | 职责 |
|---|---|
| `config/content_expression/catalog-v1.json` | 运行时精简 V1：只含有当前运行消费者的 `verified` / `composable` 项 |
| `config/content_expression/capability-inventory-v1.jsonl` | 研究全景、五轴映射、能力证据、依赖、缺口与去向 |
| `src/brain/content_expression.py` | 轻量 schema / loader；非法版本、重复 `stable_id`、未知状态一律失败关闭 |

能力状态只允许 `verified` / `composable` / `experimental` / `unsupported` / `explicitly_out_of_scope`。
全局目录语义、版本和状态只能由笛语运维通过 Git 版本更新；**不给租户管理员建设目录编辑接口或后台**。

## 四、任务冻结与修订一致性

`business_tasks.content_context_snapshot`（expand-only、可空）冻结：目录版本、原始五轴选择、
应用后的方向、透明转译、`ContentRole`、账号画像版本、私人偏好模式与实际采用的偏好版本、
明确选择的素材引用与版本。**不复制私人偏好正文**。

V2 修订只读本任务冻结快照；账号画像、目录、私人偏好或素材后来变化不得改写旧任务。
历史任务由迁移从既有 `generation_runs.input_receipt` 无损回填 legacy 快照
（`profile_version=null`、`legacy_content_role=true`）；无法可靠回填的任务不读取当前设置，
只给一句自然提示，旧成品继续可读。

## 五、权限与隔离硬边界

- 账号使用资格 ≠ 画像维护资格；
- 租户管理员只能维护**其自身组织控制**的发布账号画像；
- 区域/门店维护人必须同时满足：属账号控制组织、有该账号有效使用资格、
  `auth_grants.can_maintain_expression_profile = true`；
- 客户端传入的 account / profile / organization ID 一律不可信；
- 私人偏好在数据库层用 `app.tenant_id` ＋ `app.user_id` 双重限制，同租户管理员也读不到；
- 现存账号的控制组织只能在**唯一证据**成立时回填，存在歧义时保持 `NULL`，不按账号名、
  角色名或操作者姓名猜测。

## 九、验收结果

### A 目录

- 稳定 ID 唯一、能力状态合法、版本可追溯（`content-expression-catalog-v1`）；
- **诚实对账**：风格 `20/20`、题材 `55/55`、体裁 `41/44`，合计有定义 `116`，目标 `119`，
  缺 `3`；缺口登记为 `CAT-SOURCE-GAP-GENRE-001/002/003`，`gap_type=source_gap`，去向 F10，

  只有本人主动启用后才出现；

- OpenAPI 中与目录相关的路径只有 `GET /api/v1/content/expression-catalog`，租户管理员没有
  任何全局目录写入面。

### B 画像

五段完整校验、保存形成 V1、再次保存形成 V2、V1 不可变且仍可读、当前指针指向 V2、

新建发布账号会记录控制组织并可立即维护。
