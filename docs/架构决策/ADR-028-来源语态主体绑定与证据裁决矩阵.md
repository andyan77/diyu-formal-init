# ADR-028：来源、语态、主体绑定与证据裁决矩阵

- 状态：**ACCEPTED**
- 日期：2026-07-28
- 来源诊断：
  [UI11-D1 来源、语态、主体绑定与证据裁决收敛审计](../UI-11-语义裁决收敛诊断.md)
- 接受来源：主控 UI-12 执行裁决
- 当前消费者：UI-12 `BLOCKED`

## 背景

UI-07—UI-10 已依次关闭模型 ready 直接写入、约束冒充事实、Writer 生成制作条件、Reviewer
类型标签决定通过等问题。UI-11 把一般虚构情境放进服务端所有的 hypothesis program 后，
真实 G3 仍失败：

- 服务端插入的“假设有这样一幕：”被当成当前机构主张；
- 泛指原则与建议只因 action/cause/result span 非空，被当成已发生微事件；
- Reviewer clause 覆盖完整、跨度精确、无 uncertain。

现有 `ReviewEvidenceV1` 没有来源、unit contract、subject binding，也没有情态/体貌证据。
来源和 contract 本应由服务端掌握，不应交给 Reviewer；情态/体貌是 Reviewer 可提取的原文
证据，但不能让 Reviewer恢复 observation type 或 pass/fail 权。

## 决策

### 1. 先来源，再语义

服务端为每个可见 clause 保存不可变 `ClauseContextV2` sidecar：

- `text_source`：`server_wrapper`、`frozen_user_fact`、`frozen_brand_fact`、
  `frozen_product_fact`、`writer_unit`；
- `unit_contract`：`abstract_observation`、`recommendation`、
  `hypothetical_example`、`disclosed_dramatization`、
  `actuality_reflection`、`frozen_fact`；
- `unit_id/clause_id/exact_text/visible_order`；
- `speaker_kind`：`institutional_account`、`personal_ip_account`、`unknown`；
- `fact_ref`：只允许冻结事实 clause 持有。

每个 clause 恰好一个 `unit_contract`，禁止 `abstract/recommendation`、
`hypothesis/dramatization` 之类联合合同，也禁止读完 Writer 文本后再选合同。这些值由
Frame、program、unit skeleton、fact kind 与服务端组装顺序确定；Writer 和 Reviewer 都不能
返回或修改。相同字面只有 `server_wrapper` 来源才获得 wrapper 资格。

program validator 与 semantic reconcile 必须消费同一份 sidecar，不得各自重建一套映射。
普通抽象、明确建议、假设 wrapper/正文、演绎 disclosure/正文、真人事实/反思、H1 和 D1
必须全部有穷尽映射；未知 program、unit 或映射缺失结构失败。不得再把
`observation_only_v1` 的单 body 固定解释为 `abstract_principle`。H1 的 `hypothesis` 与
D1 的 `dramatization` 都由 Frame 和 server program 授权。

### 2. 主体绑定归服务端

服务端使用可信 scope、精确 protected names、fact_ref、结构化 speaker kind、unit contract 与
Reviewer exact subject evidence 派生：

- `none`；
- `generic`；
- `fictional_role`；
- `current_person`；
- `current_institution`；
- `protected_exact_subject`。

Reviewer 不决定主体属于谁。`speaker_kind` 必须来自冻结账号/ContentRole 结构化真源，禁止
根据账号名、角色名或画像散文猜测。若现有数据模型缺失可信结构位，只增加一个 expand-only
字段；旧行保持 `unknown`，不猜测回填。个人 IP 可以在可信边界内表达当前观点或建议，但无
frozen fact 时不能声称经历、已经发生、长期做法或具体对白。无法唯一绑定时返回
`insufficient_evidence`，不扩充题材、人物或中文失败句词表。

### 3. ReviewEvidence 最小升级

保留现有 subject、predicate、action/event、dialogue、motive、cause、result、time、
location、implicit subject 与 uncertain。V2 只增加 `modality/aspect` 这一类新语义证据，
但所有 span 都统一为可定位具体 occurrence 的对象：

```json
{
  "text": "要",
  "start": 2,
  "end": 3
}
```

索引按 Python Unicode 字符位置，必须满足 `exact_text[start:end] == text`。每个 clause
evidence 内新增：

```json
{
  "grammatical_marker_spans": {
    "modality": [{"text": "要", "start": 2, "end": 3}],
    "aspect": []
  }
}
```

它不得放在无法关联 clause 的根级数组。重复文字由 offset 区分；多重主张或关系无法唯一定位
时 `uncertain=true`。Reviewer 只做 evidence extraction，不返回：

- observation type；
- unit contract；
- subject binding；
- factuality；
- pass/fail；
- 资源；
- 修复建议。

`ReviewEvidenceV1` 继续用于 legacy/历史证据，不批量回填或改写。

### 4. 裁决顺序固定

1. 构造唯一可信 `ClauseContextV2`；
2. evidence ID、原文、顺序、occurrence offset、覆盖与 uncertain；
3. server wrapper 与 frozen fact 的结构、来源和逐字资格；
4. 仅对 writer-owned clause 派生 protected/current/generic/fictional subject binding；
5. 组合单值 unit contract、正向 modality/aspect 与
   action/dialogue/cause/result/time/location；
6. DeliveryCompiler provenance 与 resource registry。

冻结事实只做结构来源核验，不因普通语义 evidence 被二次否决。server wrapper 只做结构核验，
不成为机构主张。writer clause 出现 current institution + predicate 且无 frozen brand fact
时拒绝。

### 5. 一般表达规则

- `recommendation + generic`：只有服务端明确分配 recommendation contract，且存在正向
  modality evidence 时才允许动作；裸动作返回 `insufficient_evidence`，出现现实时间、地点、
  对白、current/protected binding 或已完成体貌时拒绝；
- `abstract_observation`：允许抽象 predicate 及不带具体情境的泛指 cause/result；具体
  action 与 time/location/dialogue/aspect 组合时拒绝；
- `hypothetical_example + server_wrapper + fictional/generic`：允许动作、关系与对白；绑定
  current/protected subject 时拒绝；
- `disclosed_dramatization`：只由服务端 disclosure 授权，真实主体边界不变；
- `actuality_reflection`：现实原文只来自 frozen user fact，Writer 只能写不新增现实的反思
  或建议；
- 证据不足时 `insufficient_evidence`，不得送 Writer 猜测性修复。

完整有效组合以诊断文档的 SDR-001—SDR-042 为规范性候选。

### 6. Reviewer 证据的证明边界

exact span 能证明“Reviewer 指出的文字确实存在”，不能形式证明“未返回的语义不存在”。
因此：

- clause 覆盖与 exact-text 覆盖不能冒充语义类别完整性；
- 不新增 `complete=true` 之类自报字段；
- 服务端只在 source/contract/binding/evidence 的正向组合足够时 allow；
- 其余组合 fail closed，并在证据中保留 `insufficient_evidence`。

### 7. 制作职责不变

叙事人物、地点、道具和声音永远不自动成为制作资源。DeliveryCompiler 仍只能投影：

- 已审 CreativeKernel unit；
- 服务端中性编译短语；
- 冻结允许资源。

本 ADR 不改变 Writer 输出或 DeliveryCompiler 业务职责。

## 选项比较

### 选项 A：只改服务端现有 V1 组合

优点：改动最少。

缺点：无法稳定区分“婆婆要尊重儿媳”和“婆婆尊重了儿媳”，只能读取汉字写规则表或继续
过拒绝。不能关闭已证明的语态缺口。

结论：不推荐。

### 选项 B：服务端 source/contract/binding + 最小 grammatical evidence

优点：保留单一服务端裁决；精确解决已出现的 wrapper、泛指建议和完成体问题；不改变 Writer、
模型、Compiler、数据表或外部合同；可用现存 raw 离线重放。

缺点：需要 occurrence-aware `ReviewEvidenceV2`、兼容解析和结构化 speaker kind；模型
evidence extraction 仍不是形式化 NLP 证明，
不可判定组合必须保守停止。

结论：**已接受。**

### 选项 C：让 Reviewer 恢复类型或 pass/fail

优点：表面实现简单。

缺点：复活 UI-09 C 的假绿根因，服务端重新失去最终裁决权。

结论：拒绝。

## 影响

如果接受：

- UI-12 只实施一个服务端纵向闭环和一个 evidence 版本扩展；
- 旧任务、V1 evidence 与 legacy ReviewerObservation 不变；若没有可信 speaker kind，
  数据库/API 只做 expand-only 字段，旧行保持 unknown；
- 必须新增正负/不足三类消费者，不再只测 allow/reject；
- Reviewer 资格失败、来源错误、frozen fact、compiler/resource 错误均不可进入 Writer 修复。

如果不接受：

- UI-11 继续 `BLOCKED`；
- 不再重跑 G3，不换模型，不建设第二 Reviewer；
- 主控需给出另一项能够区分已证明四句反例、又不依赖词表的单一裁决。

## 最迟裁决点

本 ADR 已在修改 `ReviewEvidenceV1`、`ReviewClause` 或服务端 reconcile 代码前由 UI-12
主控裁决接受。

## 明确不做

- 不改 Writer Prompt、输出或创作策略；
- 不比较/更换模型，不加 fallback、重试层或第二 Reviewer；
- 不加题材、人物、失败句或中文词表；
- 不加表、迁移、工作流、DIFY、微服务、队列或审查平台；
- 不放宽真人、品牌、商品、租户、隐私或资源边界；
- 不把 ADR 已接受冒充为 Reviewer V2 模型资格、业务验收或生产通过。

## 实施反馈

UI-12 功能 SHA `c3b3eadfb22ab21d528c42bbf58d1fd02c12456e` 已完成本 ADR 的
deterministic sidecar、V2 parser/reconcile 与 speaker kind，并通过 42 条 SDR 和六项
mutation。随后当前 `deepseek-v4-flash` 的首批 Reviewer V2 真实资格响应在 10 个 clause
中有 3 个遗漏必填 `implicit_subject` 与 `uncertain`，证据在语义裁决前即失败关闭。

该历史结果不撤销本 ADR 的服务端职责裁决；主控随后把直接原因订正为 JSON mode 不提供
Schema 保证，并授权 UI-12 原里程碑内的 strict function transport。

Strict transport 实现 SHA
`b1deb3c98889f33902e765a1ab37ffb7614d0bd5` 已证明 `/beta` strict schema、唯一强制
function、未经清洗的 V2 arguments 与 writer-owned clause 作用域可以成立。真实第一包
同时暴露两个非传输缺陷：歧义 clause 返回 `uncertain=true`，重复文字的第二个
occurrence offset 错位。服务端分别保守停止为 `insufficient_evidence` 和
`review_evidence_span`，没有接受错误证据。

因此 ADR-028 的来源、合同、主体、证据组合与服务端最终裁决仍保持 `ACCEPTED`；未成立的
是当前 Reviewer 的稳定 evidence 资格。UI-12 按既定停止线再次为 `BLOCKED`，不得用默认
值、offset 清洗、Prompt 单句补丁、随机重跑、JSON fallback 或模型替换把失败改写成通过。

## 已接受补充裁决：occurrence 选择与 offset 计算分离

主控已依据上述真实失败接受以下最小订正；ADR-028 保持 `ACCEPTED`：

- Reviewer span 不再返回 `start/end`，只返回 clause 精确 `text` 与从 1 开始的
  `occurrence`；
- 服务端在可信 clause 原文中枚举全部精确匹配，根据 occurrence 唯一绑定并计算 Python
  Unicode offset；
- 原文不匹配、occurrence 非正数、越界或无法唯一绑定继续失败关闭，不默认、不清洗、
  不重跑；
- `uncertain=true` 是一种合格的 evidence 状态，不是结构资格错误；冻结歧义样本应由
  服务端裁为 `insufficient_evidence`，且不得进入 Writer 修复；
- 服务端可在最终审计 evidence 中保存自己计算的 `text/start/end`，模型不获得 offset
  决定权。

Strict function transport、单一 sidecar、SDR-001—SDR-042、四态服务端裁决和现有
事实／主体／资源／租户边界不变。该补充裁决不授权换模型、fallback、第二 Reviewer、
失败句 Prompt 补丁或 UI-13。

## occurrence 补充裁决的实施反馈

实现 SHA `1da4811d059b8865f1ffc0673702a169d5f2d986` 已把 strict schema 收为
`text + occurrence`，由服务端精确解析为内部 `text/start/end`。直接消费者证明非正、
越界、原文不匹配、模糊匹配与旧 offset raw 均失败关闭；`uncertain=true` 可结构通过，
最终为 `insufficient_evidence` 且不可送修复。

冻结 6-clause 小包在文档 SHA
`91be39cc5b8e993d790e9e59c59b0eb3e7d49d1c` 上通过真实 strict 资格，包含真实指代
`uncertain` 与重复片段 occurrence 1/2。但随后完整 G3 的 16-clause Reviewer 响应中，
12 个只在所属 clause 出现一次的 evidence text 被返回为 occurrence 2 或 3。服务端按本
ADR 正确失败关闭，没有清洗或默认第一次。

这不撤销 ADR-028 的职责裁决，也不表示服务端矩阵错误；它证明当前 Reviewer 在完整成品
规模下尚不能稳定履行“按所属 clause 选择 occurrence”的证据提取职责。UI-12 已命中明确
停止线并置为 `BLOCKED`。G3 provider-call 封装 SHA-256 为
`598a879585a9f2837b7d22be7259417112b1d515bffd096ddf5e01681f0e9423`，
最小诊断 SHA-256 为
`c050013e3d7ba0453e78d715b84ba5533572b2f0f438873ab3465b828591af0e`；
正式 root-only 证据位置见 UI-12 执行包第 14 节。

当前不得把小包资格、strict transport 或服务端正确拒绝冒充完整业务通过，也不得以
fallback、默认 occurrence、模糊匹配、随机重跑、失败句 Prompt 或 UI-13 静默绕过该结果。

## 已接受补充裁决：模型不再提供任何地址

完整 G3 已证明 occurrence 序号仍是模型不稳定理解的确定性地址。主控因此进一步接受：

- Reviewer quote 不再包含 `start/end/occurrence`；
- 服务端只在可信 clause 内做 exact match；唯一匹配后计算 Unicode offset，零次或多次
  均失败关闭；
- Reviewer 必须通过更长 exact quote 消除重复短语歧义；无法唯一提证时返回
  `uncertain=true`；
- 服务端内部规范化 evidence 仍保存自己计算的 `text/start/end`，其余 SDR 与四态裁决
  不变。

该修正是 ADR-028 内部责任边界收敛，不是新 ADR、新里程碑或事实标准放宽。运行时失败关闭
与开发治理分离：接口、schema、parser、binder、fixture、oracle 和职责内 Prompt 缺陷均
在 UI-12 内持续修复，只有产品、安全、供应商或历史兼容边界改变才停工。

## quote-only 实施反馈与当前能力边界

quote-only strict contract、服务端唯一 exact quote 绑定和 Unicode offset 规范化已经
在定向反证及完整 G3 中成立。零匹配、多匹配和 `uncertain` 均保守停止；模型不再拥有任何
地址决定权。因此 ADR-028 关于“来源／合同 sidecar 是权限真源，Reviewer 只提 evidence，
服务端唯一裁决”的决定继续为 `ACCEPTED`。

完整 G4 随后暴露了不同层次的阻断。机器曾放行包含未冻结“伴侣”身份、动机和示例对白的
成品，人工全文审阅将其识别为假阴性。既有 evidence 合同据此最小增加通用
`relationship_role` 精确证据类别，而没有增加题材或失败句规则；服务端也只允许冻结真人
事实中真实存在的关系角色。

在最终 WIP `c4b8953…` 上，Reviewer 对修复稿 10 个 clause 返回 32 项 evidence 且
`uncertain=0`，却没有提取任何 `relationship_role`、`motive` 或 `dialogue` evidence；
可见正文仍包含未冻结关系类别和动机解释。服务端抓住另外两项配文问题并失败关闭，但不能
把缺失 evidence 当成“没有违规”。

这不是 ADR-028 服务端权限模型的反例，而是其输入 evidence 的真实能力前提尚未成立。当前
边界下无法通过服务端算法从“模型没有返回某类 evidence”确定地恢复该语义；继续需要人物／
关系／动机词表、Reviewer 单角色处置或降低真人事实边界。前两者改变本轮禁止范围，后者
违反已接受产品合同。ADR 保持 `ACCEPTED`，UI-12 保持 `BLOCKED`，等待主控只裁决该
Reviewer 单角色能力阻断。

## 已接受补充裁决：闭合问题集取代开放 evidence 枚举

第 16 节 G4 已证明：开放式 evidence 列表即使 schema、coverage 和 quote 都合法，也不能
证明未返回的关系、动机或对白风险不存在。该缺口不通过继续增加类别、失败句 Prompt 或
人物词表处理。

ADR-028 补充接受：

- 服务端从可信 `ClauseContextV2` 为每个 writer-owned clause 生成完整、稳定的风险问题
  集；
- Reviewer 只对服务器给出的 `question_id` 回答 `present/absent/uncertain`，不能省略、
  增加、重复问题，也不返回最终允许性；
- `present` 携带唯一 exact quote 与必要 operand；`absent` 不携带 quote；
  `uncertain` 保守为 `insufficient_evidence`；
- 服务端根据闭合回答派生 Claim Inventory，再与 Frame、Plan、fact refs、protected
  subjects、program disclosure 和资源边界确定性对账；
- source、unit contract、speaker kind、fact_ref 和最终 pass/fail 仍全部归服务端。

固定风险维度是 subject binding、relationship claim、actual event、dialogue
attribution、motive/mental state、cause/result、time/location/possession、
institutional/product claim、statement mode 与 disclosure。它们是产品事实权限，不是
题材词表；不同 program 可以增加直接适用问题，但不得静默删除人物、关系、事件、对白、
动机、机构与语态风险。

该补充不改变 Writer、frozen fact、DeliveryCompiler、一次修复、legacy、RLS、DM01 或
AIGC，也不授权第二 Reviewer、fallback 或供应商变化。UI-12 恢复 `ACTIVE`；真实 G4 与
完整业务轮通过前，本补充只表示责任合同已接受，不表示能力成立。

## 闭合问题集实施结果与非 Reviewer 阻断

闭合问题集已在完整 G4 上成立：Reviewer 对每个 writer clause 的固定风险问题逐题回答，
服务端验证全集、唯一 quote 与 operand 后派生 Claim Inventory；初稿的当前用户现实扩写
被拒绝，唯一 affected-unit 修复后完整复审通过。人工阅读全文确认冻结用户事实未被增删或
扩写。因此本 ADR 针对“开放 evidence 无法证明漏提风险不存在”的责任修正已经得到真实
纵向证据。

随后 G2 的最终 WIP `d4d2818d23b453d6798ab7a60709d2df28610113` 在不向 Writer
暴露商品 frozen fact 时，Writer 仍把未知 SKU 猜成电子产品并补造多项规格、性能和适用性；
闭合 Reviewer 与服务端均将其判为 `unsupported_product_claim`，一次修复后仍失败关闭。
这不是本 ADR 的 evidence 或最终裁决失效，而是本 ADR 明确“不改变 Writer、frozen fact、
DeliveryCompiler 职责”后留下的相邻接口矛盾：当前没有角色负责把服务端冻结商品事实
编译成既可审又有创作价值的商品文字。

## 已接受补充裁决：可信商品事实进入创作表达

主控已解除上节待裁决事项，ADR-028 保持 `ACCEPTED`：

- 服务端构造不可变 `ProductFactPacket`，冻结精确商品身份、结构化值、可公开
  canonical text、来源、版本、适用范围、允许主张类别与禁止推导；
- 服务端从 Packet 生成版本化 `ImmutableFactBlock`，商品硬事实只通过该块原样进入成品；
- Writer 只读 Packet 与事实块摘要，可以选择既有事实块及顺序，但只返回 block 引用、
  creative unit 与可选 `claim_refs`，不得返回事实正文或创建 ID；
- `claim_refs` 只用于服务端审查定位，不构成事实许可；creative clause 不得重新承担
  商品硬属性或数字；
- Closed Reviewer 继续逐题提证，服务端核对 Packet、允许类别和禁止推导后唯一裁决；
- DeliveryCompiler 只组合已审 creative unit、原样 fact block 与登记资源。

该补充不允许模型按不透明 SKU 猜品类，不允许资料来源／品牌约束／制作资源互相冒充事实，
也不改变旧任务 legacy 读取。UI-12 恢复 `ACTIVE`；历史 G2 失败继续作为负向证据，只有
新实现同 SHA 的完整业务与生产门成立才可进入 `REVIEW`。
