## 背景

首期内容系统需要同时保持品牌一致性、用户创作空间和真实能力边界。研究稿中的
20 条风格、55 条题材和 44 条体裁是原始能力全景；它们后续必须映射到本 ADR 的五轴目录，
但不等于当前代码已经支持或真实品牌已经验证。
若把全景直接做成前端选项，会让候选能力冒充产品能力；若完全不提供方向控制，又会削弱
用户自主选择和后续真实试点对能力缺口的观察。

M6-3 最终只完成冻结八卡中的 Q1—Q7 `4/7`，Q2/Q4/Q7 失败，审查 A 失败、审查 B
通过，已被 `SUPERSEDED` 而不是关闭。该历史证明原验收方法和串行依赖不再适用，不证明
内容质量问题已经解决，也不构成本 ADR 已实现的证据。

## 决策

### 1. 内部使用五轴内容表达空间

系统内部以五个彼此独立、可组合的轴描述内容表达空间：

1. 题材；
2. 内容机制或讲法；
3. 表达风格；
4. 媒介形式；
5. 连续与参与方式。

五轴是目录和能力对账视图，不是新的内容本体、生成流水线或用户必须填写的五步表单。
既有 P1—P5、平台/媒体合同、`PublishingAccount + ContentRole`、品牌表达基线和连续系列
继续作为运行主干。

### 2. 首期用户入口保持轻量

- 普通用户继续以自然语言交互为主；
- 前端首期只提供一个可选“创作方向”面板；
- 独立“设置”页面暂缓，真实使用证明有必要后再实施；
- 精简 V1 是默认可见目录；
- 研究稿 20/55/44 只作为完整能力全景和对账目标，不得全部显示为已支持。

目录条目后续逐项使用以下能力状态：

- `verified`：已有当前范围的直接实现和验收证据；
- `composable`：可由已验证能力安全组合，但尚无独立真实试点；
- `experimental`：允许有界试用，不能作为稳定承诺；
- `unsupported`：当前不能交付；
- `explicitly_out_of_scope`：当前明确不做。

### 3. 品牌冲突采用透明转译

当用户选择与品牌风格存在冲突时，系统：

- 保留用户原始创作意图；
- 自然说明怎样转译成品牌可成立的版本；
- 不静默夹回、覆盖或替换用户选择；
- 对硬事实、身份、权限和明确品牌红线继续使用最小替代或拒绝。

这不是允许系统编造品牌、顾客、门店或商品事实。无来源的经营做法、既往事件和现实经历
应转为当前立场、条件性建议或删除。

### 4. 体型相关标签只允许主动启用

- 只能由租户或用户主动启用；
- 系统不得自动推断体型；
- 不得贬损体型；
- 不得承诺穿着效果。

### 5. 目录与偏好的控制权

- 全局目录语义、版本和能力状态只由笛语系统运维维护；
- 租户管理员不得修改全局目录；
- 租户管理员只维护总部层级发布账号的表达设置；
- 总部可以按既有管理关系创建、停用或撤销区域/门店账号的使用资格，但账号使用资格不授予
  总部修改区域/门店账号画像或个人偏好的权利；
- 租户管理员不得修改区域代理或门店用户自己的创作偏好；
- 区域和门店用户可以维护自己的最小偏好；
- 普通生成、聊天、平台数据和机器评分不得静默改写偏好或账号人格；
- 全国统一的强制账号人格模板、复杂参数化编辑和自动人格学习不进入第一阶段。

### 6. 实际启用发布账号的五段人话画像

只有已经或即将正式对外生产内容的 `PublishingAccount` 必须绑定一个当前主
`ContentRole`，并由一份已确认、可版本化的账号表达画像承载以下五段人话信息：

1. **表达身份**：这个账号代表谁、从什么位置说话；
2. **真实资格与权威边界**：凭什么说、哪些内容不能冒充知道或经历过；
3. **主要受众关系**：长期服务谁、与受众保持什么关系姿态；
4. **可经营的内容领地**：通常适合观察和持续经营哪些生活、工作与专业领域；
5. **实际制作条件**：当前可长期依赖的一人/多人、设备、场地与素材条件。

五段画像是账号级人话草案和运行投影，不是五张表、五步强制表单、参数矩阵或新的本体
对象。系统可以使用行业角色模板、品牌战略基线和自然交流起草；模板只提供建议，必须由
发布账号控制组织中具有账号表达维护资格的主体确认后才成为当前版本。

总部发布账号只由具有总部管理资格的租户管理员在总部范围维护；区域和门店发布账号由其
控制组织授权主体维护。本人只有在该账号明确是其人物型账号、且本人同时具有账号表达维护
资格时，才能确认该账号画像。个人默认表达人设和私人协作偏好继续只由本人维护，不能被
租户管理员或账号画像覆盖。
同一发布账号任一时点只使用一个当前画像版本；新确认形成新版本，历史任务继续保留当时
实际使用的 `ContentRole` 与画像版本。模板升级、普通聊天、一次生成、普通内容修改、
平台数据和机器评价均不得静默改写；用户在有权编辑画像的入口主动修改并确认时可以形成
新版本。

题材、讲法、风格、媒介形式、时长和本次创作方向仍按任务变化，不固化为账号人格。账号
画像决定表达位置与资格边界，不成为知识访问权限或逐知识门禁。

画像第五段只保存默认可长期依赖的制作条件。本次人物、设备、场地和素材仍以当前任务明确
输入为准；任务条件不得自动回写画像，画像默认也不得冒充本次资源已经存在。

本人默认表达人设也不能静默进入任意企业发布账号：企业发布账号始终以该账号当前的
`ContentRole` 与五段画像为表达真源；只有该账号明确是本人型发布账号，或账号控制组织
已经允许本人身份参与当前表达时，才可在该范围使用本人默认表达人设。

### 7. 三条长期核心目标

内容能力长期围绕以下三条护城河发展：

1. 品牌一致性下的表达广度；
2. 不同租户的实质差异化与反串味；
3. 自媒体内容市场竞争力与持续进化。

第三项只说明产品发展目标。平台流量、排名、爆款、GMV、销售或市场竞争结果必须由真实
发布和平台反馈证明，不能由模型自评、合成黄金或绿色测试替代。

### 8. 里程碑承接

- M7-1：只做真实门店 DM01，不加入内容目录；
- M7-2A：实现版本化目录 V1、可选创作方向、个人默认偏好与私人协作偏好最小控制、
  实际启用发布账号的五段画像及确认/版本/组织权限、轻量内容机会与计划、合法素材选择、
  能力状态和未满足需求；生成留痕能够追溯本次角色画像版本。画像在现有身份/上下文抽屉
  展示只读摘要，有维护权者在同处编辑确认；总部管理员可从既有账号管理进入，区域/门店
  维护者从自己的账号身份卡进入，不新增设置页，所有权限仍由服务端控制组织判定。透明
  转译必须保留用户原选择，并用一句人话说明保留什么、因哪条品牌边界怎样转译；用户可以
  继续调整，硬红线只给最小替代或拒绝；
- M7-2B：使用一个总部岗位型账号和一个门店人物型账号的已确认五段画像，各完成至少
  三篇连续系列；验证账号差异、身份/权威边界、系列连续、透明品牌转译、内容质量、
  R/O 实际表现、平台重编译、按需在地搜索/趋势上下文、真实商品内容与需求缺口；
- M7-3：完成第一阶段整体验收，明确检查账号画像版本追溯、权限与偏好隔离、同品牌总部/
  门店账号的实质差异、同品牌多元表达、三平台规则时效和两条真实业务路径。跨品牌与
  跨租户的真实差异只在第二个真实对象出现后验证；首期只保留合成隔离反证并列为未证明。

M7-2B 验收最终当前版本及自然协作过程，保留 V1/V2；不要求原始模型首稿永远完美，也
不得靠随机重跑碰运气。制作资源属于可人工复核的内容质量，优先省略、替代或降级；只有
用户明确要求的核心成果确实缺少不可替代资源时才作一次最小追问。权限、租户隔离、个人
信息、内部信息、明确商品事实冲突和正式硬禁项继续失败关闭。

### 单一有界修复轮补充（2026-07-25，迁移 `20260727_21`）

本 ADR 的"服务端按账号控制组织判权"由此收紧为**只认明确声明**：

- `content_accounts.control_organization_source` 区分 `unset / inferred / declared`。迁移按
  `publishing_account.created` 事件推断出来的值记为 `inferred`，**不授予任何维护资格**；
  只有新建账号时明确指定，或该租户有权主体一次声明（留痕复用既有 `activity_events`），
  才成立。新建账号不再默认取创建者所属组织。
- 维护资格检查与版本写入进入**同一数据库事务**；当前画像读取必须 tenant + account + profile
  三者同时匹配，并由 `UNIQUE (tenant_id, account_id, id)` 与复合外键在数据库层封死。
- 任务快照同时冻结实际使用的 **ContentRole 名称与表达边界**，修订只重放冻结身份。
- 私人协作偏好成为真正的柔性协作输入（进入模型上下文），但不写入租户可见的任务快照或通用运行
  回执；并提供真正的临时无偏好会话（目录、机会、生成、修改都不读不写）。
- 自然语言透明转译只接受**声明别名的精确命中**，无法可靠映射的自由表达原样保留；仍不做模糊
  风格检测、关键词黑名单、第二模型或审核 Agent。
- 笛语运维的未满足需求分类与回告入口只走既有受控函数边界，不建工作流平台、队列或审批状态机。

因此当前生产的真实 `笛语服饰品牌官方账号` 控制组织为 `inferred`，**没有任何主体可以维护它的
画像**，等待品牌方有权主体明确声明；这是 M7-2B 的启动前置之一。

> **该最后一句的“M7-2B 启动前置”已被 2026-07-25 的 M7-2B 运行化裁决取代。**
> `inferred` 仍然不授权，真实账号正式入驻时仍须明确声明；但 M7-2B 软件验收改用独立的
> `synthetic_business_fixture` 作用域，不再等待真实账号画像或真实商品。

### 主控终审极小返工补充（2026-07-25，无迁移）

决策 3（透明转译）与决策 5（目录与偏好的控制权）由此补齐三条边界：

- **同一轴的优先级**固定为：本次面板明确选择 → 本次自然语言中**未被否定的**精确标签/别名 →
  已保存默认。保存默认是常驻便利项，**不得压过本次自然要求**；`origin` 如实记为
  `explicit / natural_text / default` 并冻结进快照。
- **最小否定语义**：`不要 / 不想 / 别 / 不用 / 取消` 五个精确词，仅在紧邻标签前 4 个字符内、
  不跨句读符号时成立；同一提及只算一次（长写法优先，嵌套的短别名不重复计数）。**正向应用**
  仍只限带 `restrained_variant` 或体型相关的条目——它必须复用可见的克制机制；**拒绝**可作用于
  任何已声明条目，因为拒绝只会拿掉东西、永远不会引入新选项。被拒绝的条目若正是该轴的已保存
  默认，则本次不生效，**已保存默认本身不被修改**。仍不做模糊风格检测、关键词黑名单、第二模型
  或审核 Agent。
- **修改一律不读今天的私人偏好**：同目标修改只重放任务快照；跨目标改编是同一任务条件的重新
  编译，显式以 `use_personal_preferences=false` 运行。修改接口读取
  `X-Diyu-Preference-Session`，临时无偏好会话只能让这条更窄，不能把它打开。
- **私人协作说明的产物边界**：它只控制协作方式与表达取舍，**成品中不得引用、复述或解释其
  原文**。该约束写在既有适配器边界的指令里（随说明交付的那一行与创作要求清单），不新增审查层、
  重试层或第二模型——它是给模型的工作指令，不是对产出的机器过滤，因此真实模型下属于**提示级
  约束**，不得被描述为已被机器强制。

## 证据等级

本 ADR 记录的是**用户已确认规划**。M7-2B 已由主控终验 `CLOSED`，并以等深模拟资料证明本
ADR 的内容协作运行能力；M7-3 也已通过主控产品级独立终审并 `CLOSED`。这些只证明当前首期
代表性范围成立，仍没有证明：

- 20/55/44 已全部登记、全部支持或验证；
- 五段账号画像、组织权限与版本追溯已由**真实品牌主体**确认或真实验证
  （当前只有隔离夹具证明软件能力；真实笛语账号画像仍待有权主体保存）；
- 不同真实租户已经形成充分差异化；
- 真实平台流量、爆款、排名、GMV 或销售；
- 内容市场竞争力已经得到真实市场证明。

M6-3 的 `4/7`、审查 A 失败和回退历史继续完整保留，不因本 ADR 被改写为成功。

## M7-2B 运行化补充：等深模拟业务与人类验收投影（2026-07-25）

本补充只运行化 ADR-027，**不改变**画像、偏好、目录或事实的长期含义：

1. M7-2B 的组织、表达身份、五段画像、商品和门店种子可以明确标记为
   `synthetic_business_fixture / 等深模拟业务资料`。它们必须进入正式生产表、正式 API、
   正式 FORCE RLS 和正式 DeepSeek 路径；不得使用测试旁路、stub、固定成稿或隐藏接口。
2. `synthetic_business_fixture` 是事实语义标记，不是权限豁免。两个根表达账号分别有明确控制
   组织、实际演示操作者、五段画像和平台载体；平台载体只承接媒体重编译，不连接平台、不共享
   密码、不自动发布。
3. 演示商品事实仍需 tenant + brand + 来源 + 事实版本 + 适用范围，只允许陈述已登记的品类、
   颜色、结构/轮廓和肉眼特征。它不等于真实在售商品，不得推导价格、库存、性能、销售、设计
   动机或企业采用。
4. 任务继续冻结实际使用的画像、商品、系列前情、目录方向和私人偏好模式；生成、修改、读取、
   复制、导出、平台重编译或表现记录都不得反向修改这些输入真源。
5. 租户管理员获得一个**只读人类验收投影**：从正式对象实时展示演示身份、五段画像、六篇源
   成品全部版本、系列前情使用数量和六份平台当前成品。它不复制内容到第二张表、不建立第二套
   状态机，不向普通用户显示技术 ID、GenerationInput、P1—P5 编号或规则轨迹。
6. 演示进入沿用正式自然人认证与一次性重置链接。没有共享演示密码、认证旁路或平台凭据；
   普通租户用户、租户管理员与笛语运维入口继续隔离。

因此本轮可以证明真实生产代码、数据库、RLS、认证、DeepSeek 和软件协作能力，也可以证明同一
品牌语境下总部与门店演示身份的表达差异；不能据此宣称真实员工使用、真实商品采用、真实发布、
市场流量、销售、企业采用或多个真实租户之间的市场差异化。

## M7-2B 主控终审返工运行化补充（2026-07-25）

本补充不改变 ADR-027 的长期数据含义，只关闭自然修改、可见成品和一次性进入的运行边界：

1. **自然修改的父版本是待修改稿，不是事实来源。** 同目标修改继续重放该任务冻结的账号画像、
   商品事实、系列前情、目录方向和私人偏好模式；既有 DeepSeek 编写器可同时读取父版本正文，
   以落实“只改点名处、其他保留”。父版本不能承载新现实事实，商品、账号、人物和资源仍只认
   冻结快照与可信来源；事实审查和失败原子性不放宽。
2. **内部语义合同与用户成品只做一份存储、一个投影。** P1—P5 合同、事实来源和账号方向继续
   留在任务快照、运行留痕和校验数据中；新生成响应、当前版、历史版、演示验收页、复制和导出
   共用一个服务端人话投影，移除编译脚手架，只展示自然概要、标题、完整正文/台词、制作说明、
   发布辅助和 AIGC 提醒。不新增内容表或第二编译器。
3. **一次性链接的最小安全语义。** HTTP/HTTPS `/activate/` 不记录原始 token，应用日志只记
   脱敏路径；同一用户签发新链接时同事务失效旧未使用链接，任一链接成功使用时同事务失效其余
   链接并撤销旧会话，留痕复用既有 `activity_events`。这不是新审批流，也不改变租户用户、
   租户管理员和平台运维三入口的隔离。

本补充没有引入第二模型、审核 Agent、评分器、关键词黑名单、第二内容编译器或新增重试层。

## M7-2B 唯一有界收口运行化补充（2026-07-26）

本补充不改变账号画像、平台父子关系或事实的长期含义，只明确跨平台任务后续自然修改与一次性
入口日志的既有语义：

1. **平台改编语义随真实改编任务延续。** 从一个渠道或媒体重编译到另一个渠道或媒体后，该
   平台任务的同目标后续自然修改继续携带原源版本的人话 `source_description`，使模型知道它
   正在修订一份跨平台成品；`parent_version_id` 仍只指向创建该平台任务时冻结的源版本，不被
   后续修改改写。只有渠道或媒体实际变化时才成立；同渠道同媒体的普通 parent 不得被误标为
   平台改编。
2. **源说明不是新的事实来源。** 后续修改继续只认任务冻结的画像、商品、系列前情、方向与
   私人偏好模式；源说明和父稿只帮助保留改编意图。tenant + brand + account + created_by
   仍由服务端可信会话解析并失败关闭，生成失败仍不产生半版本。
3. **激活 URL 不进入边缘日志或引用链。** 正式及 maintenance 的 HTTP/HTTPS `/activate/`
   location 均位置级关闭 access/error token 日志并返回 `Referrer-Policy: no-referrer`；
   正式 HTTP 入口丢弃原始 URI 后跳到 HTTPS 安全首页。应用只记录脱敏路径；链接事务失效与
   会话撤销语义沿用上一补充。

该补充没有引入平台 Agent、第二模型、审核 Agent、新重试层、关键词拦截器、第二编译器或新表。

## M7-3 第一阶段整体验收运行化补充（2026-07-26）

M7-2B 经主控独立产品级终验后正式 `CLOSED`。M7-3 只复用 M7-1、M7-2A、M7-2B 的不可变

能力目录和反馈候选之间的接缝；它不把整体验收扩成新功能开发。

M7-3 最终只修复正式 `/content`、`/display` 服务端 bootstrap 与 React
工作壳之间的接缝，使正式路由冻结的账号、`ContentRole`、载体和资料性质不再被通用会话上下文
覆盖；补齐平台方向来源留痕；并修正九条目录缺口的未来去向。没有重建 M7-2B 成品、改变
P1—P5、增加状态机或扩张业务范围。

反馈接缝必须区分两种能力。本轮以正式 `synthetic_business_fixture` 新建一条未满足需求候选，

不能读取。探针前后受保护任务快照、知识/画像/偏好/系列前情以及目录文件均未变化。该证据只证明
“未满足需求候选”受控闭环；[ADR-011](ADR-011-发布反馈自愿提交与禁止生成门控.md) 确认的

能力目录无孤儿对账只更正去向，不升级能力状态。`CAT-TOPIC-TEACH-07`、
`CAT-TOPIC-NEWITEM-01`、`CAT-TOPIC-NEWITEM-06`、`CAT-TOPIC-TREND-01`、

对象；事实准确、受众回报、真人可说可拍、平台原生重编译、系列连续和反馈候选入口只构成内容
竞争基础，不等于流量、排名、爆款、GMV 或销售。
