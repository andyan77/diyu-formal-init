## 2. 唯一结果

建立单一、服务端所有的 clause 权限链：

```text
NarrativeFrame + program + unit skeleton + fact kind + speaker kind
→ ClauseContextV2
→ occurrence-aware ReviewEvidenceV2
→ 服务端 subject / contract / grammatical evidence 裁决
→ 最多一次合法 affected-unit 修复
→ DeliveryCompilerV1
```

Writer 继续只返回 `unit_id + text`；Reviewer 继续只提取 evidence；DeliveryCompiler
继续只投影已审文字、中性短语和登记资源。模型、Writer 策略、事务边界与生产职责不改变。

## 3. 实现合同

1. `ClauseContextV2`
   - 保存 `clause_id/unit_id/exact_text/visible_order/text_source/unit_contract/speaker_kind/fact_ref`；
   - 每个 clause 恰好一个 contract；
   - program validator 与 semantic reconcile 共同消费同一 sidecar；
   - Writer、Kernel 自报类型和 Reviewer 类型均无授权权；
   - 未知 program/unit 或映射缺失结构失败。
2. `ReviewEvidenceV2`
   - Reviewer 每个 span 只返回 clause 内的精确 `text` 与从 1 开始的
     `occurrence`；服务端在可信 clause 原文中枚举全部精确匹配并计算 Python Unicode
     `start/end`，形成内部规范化 evidence；
   - 每个 clause 内增加 `grammatical_marker_spans.modality/aspect`；
   - 漏、重、额外 clause、原文/顺序不一致、伪 span、非正或越界 occurrence 均结构
     失败关闭；
   - `uncertain=true` 是合格的诚实 evidence；服务端必须裁为
     `insufficient_evidence`，且不得送 Writer 修复；
   - V1 只作 legacy/历史 raw 读取，不回填。
3. speaker kind
   - 只接受 `institutional_account/personal_ip_account/unknown`；
   - 来自 ContentRole 结构化真源并冻结进新任务快照；
   - 旧行与旧快照保持 unknown，禁止按名称或画像散文猜测；
   - 个人 IP 可表达当前观点/建议，不能无事实声称经历、已发生、长期做法或具体对白。
4. 服务端裁决顺序
   - sidecar → evidence 资格 → wrapper/frozen fact 结构 → writer-owned subject →
     单值 contract + grammatical/event evidence → compiler provenance/resource；
   - frozen fact 和 server wrapper 不被普通语义规则二次否决；
   - `insufficient_evidence` 及结构、来源、事实、program、compiler、resource 错误不得送
     Writer 修复。
