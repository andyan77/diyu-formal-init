# 笛语产品化 HTML 原型 UI-01R

## 这次要确认什么

UI-01R 不再用页面数量证明产品完整。它只交付一套可以连续浏览的核心产品方向，用来确认：

- 首页是否讲清“模糊表达如何被理解并成为完整表达”；
- 用户是否能按任务进入内容、陈列、品牌管理或运维工作；
- 产品语言、信息层级和视觉结构是否足以进入下一轮高保真 HTML；
- 评审工具是否已经与裸产品页面完全分开。

这套静态文件不连接接口、不保存数据，也没有修改正式 React 或生产系统。

## 新的信息架构

全站收成五个产品空间：

1. 公开与认证：公开首页、三个隔离入口及激活流程；
2. 内容工作空间：用户首页、自然输入、可选方向、完整成品、修改、历史、系列与私人空间；
3. 陈列工作空间：商品与现场输入、空间关系、执行顺序和局部调整；
4. 品牌管理：品牌概览、品牌表达、账号定位、商品/组织素材和内容演示；
5. 笛语运维：租户、基础服务与需求反馈。

旧 UI-01 的 19 张页面继续保留，但只作为功能覆盖盘点与历史反例。UI-01R 的六张 HTML 是决定全站方向的代表页，不表示其余能力被删除；它们后续可以落在页面状态、标签、抽屉或次级页中。

## 四条可走通的任务旅程

- 公开首页 → 租户用户登录 → 用户首页；
- 自然输入 → 展开可选创作方向 → 当前成品 → 自然修改 → 历史版本；
- 商品与现场输入 → 陈列参考方案 → 阅读空间关系与执行顺序 → 局部调整 → 新当前方案；
- 品牌管理登录 → 品牌概览 → 品牌表达/账号定位 → 内容演示。

评审壳另提供运维登录和激活后进入对应入口的路径。登录、激活、修改和局部调整都有明确页面落点，不再用一次提示代替流程结果。

## 三套动效

| 方案 | 时长 | 一句话叙事 | 判断 |
|---|---:|---|---|
| A · 种子找到声音 | 7.2 秒 | 弱小、模糊的表达种子经历犹疑与分叉，被理解、整理并找到方向 | **执行侧推荐**；与笛语核心价值及一句话到成品的因果最直接 |
| B · 留白形成关系 | 7.4 秒 | 两段各自成立的表达，因为恰当留白而形成关系 | 最安静、关系感最好，但产品含义更抽象 |
| C · 编辑留下重点 | 6.9 秒 | 拥挤片段经删减和排序，最后留下清楚焦点 | 编辑与陈列感最强，但需避免像排版工具 |

三案在动画阶段都不显示说明文字，点击画面可跳到定格，评审页可重播；减少动效偏好下直接显示正式 Logo。最后一帧都直接引用
`assets/brand/diyu-vi/svg/diyu-logo-primary.svg`，没有重画标志。

## 视觉与交互判断

- 正式 Logo 与少量品牌标题保留宋体气质，任务、表单和数据以清晰无衬线字体为主；
- 墨黑、呼吸白、石灰灰承担信息层级，朱砂只给关键动作和方向；
- 内容工作台用对话与完整成品双工作面，移动端只切换“对话 / 成品”；
- 陈列页的主视觉是挂杆空间关系，不借用内容工作台结构；
- 品牌管理围绕业务对象和一个真实缺口，不铺就绪说明卡；
- 运维围绕优先待办、租户关系和反馈队列，比普通页面更密集；
- 每个裸产品页最多一个实心主动作，触控目标不小于 44px。
