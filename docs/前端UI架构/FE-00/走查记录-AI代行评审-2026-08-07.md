## 一、五张任务卡逐项评审

### 任务 1 · 「你今天想发一条内容，从这个页面开始，你会先做什么？」（`#fe00-today`）

**判定：通过。** 首屏是一个问题（"陈曦，今天想完成什么？"）+ 四张具名动作卡
（先了解一下 / 找个选题 / 评估一个想法 / 直接做一条），每卡一行大白话说明。
对比参照系：ChatGPT 首页用空输入框 + 建议气泡，仍要求用户先会提问；本设计更进一步，
用四个动作卡**正面回答**了立项动机里的核心痛点"用户面对系统不知道从哪下手"。
机会卡（现在值得做的）带理由与来源徽标（已确认资料 绿 / 系统推导 灰），
不造假数据。发现一处歧义 → 修改清单 **F1**。

### 任务 2 · 「讲讲店里不追着讲解这件事，走到可以开始制作为止」（`#fe00-advisor`）

**判定：通过。** 左侧对话流（用户气泡深色右置、参谋气泡左置）即 ChatGPT 体感；
右侧"本次将使用的品牌依据"面板**常驻不折叠**，逐条带"已确认"绿徽标与
"这条不对"反馈入口。推荐以 A/B 两张方向卡呈现，各带"按这个继续"；
追问只有一张卡（带上 / 不带 / 跳过），可跳过、不连环——符合 B1 口径。
"模型自带知识"以虚线徽标区分，脚注明示"不计入品牌依据，只作提示"——
符合 D-COMM-08。**追加观察项**：切换发布账号后界面明示
"总部账号那条草稿留在总部账号里，切回去就能看到"（原型 L387）——
直接回答了"刚写的字会不会跟过去"，符合 AdvisorDraftV1 跨账号规则。

### 任务 3 · 「这一屏在问你什么？你会点哪个？」（`#fe00-proposal`）

**判定：通过。** 标题"确认这次要做的内容"+ 副题"确认后才开始制作。
任何一处都可以直接改。"——一屏只问一件事，且明确这是制作前最后一次改。
五个分组全是大白话（要表达什么 / 说给谁 / 发在哪 / 必须避免 / 会用到的依据），
依据组给出计数 +"全部已确认"徽标。唯一实心主动作"确认并开始制作"，
次动作"再聊聊"。无任何内部合同名。布局留白问题 → **F2**。

### 任务 4 · 「制作包里哪些能直接用，哪些还要你自己确认？」（`#fe00-package`）

**判定：通过。** 步骤条目：序号 + 动作名 + 来源徽标 + 台词块 + 字幕对应
（"字幕 1／3：…"）。四态徽标可分辨：已确认（绿）/ 系统推导（灰）/
建议·待人工复核（琥珀，且正文内嵌"这条只是建议，用前请自行确认版权"）/
缺资料（描边红）。**琥珀误读**是走查汇总口径中的红线项：本原型用
"非绿配色 + 成对说明文案"双保险，专家判定误读风险低——但"徽标与说明成对出现"
必须作为实现约束带入 EXE-07（见 F4 备注）。右侧"本版依据"面板常驻；
决策区"采用这一版"唯一实心，"我已经手动发布了"配"没有自动发布……只留痕，
不对外发送任何内容"——发布语义诚实。

### 任务 5 · 「刚才那次失败了，你会怎么办？」（`#fe00-failure`）

**判定：通过。** 人话标题"这次没能做完"+ 原因说明 + **原输入完整保留在下方** +
唯一实心动作"用原输入重试"+ 次动作"看看是哪一步"；右侧明示
"上一版 V1 仍然完整保留，可以随时打开"。无死胡同、无责备语气、无技术堆栈词。
