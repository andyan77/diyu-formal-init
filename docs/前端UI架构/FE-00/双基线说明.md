# 双基线说明 / Why EXE-01 has two base commits

监理审查发现 4 提到「包内双基线不一致：回归对照用 `8c9f2ac`、scope 断言用
`af20ae5`」。本文说明**两个基线各自证明什么**、**为什么不是同一个**、以及
**这个不一致有没有实际后果**。结论先说：**没有后果，两个基线对所有被证明的文件
逐字节相同**——下方给了可复算的证据，不是断言。

---

## 一、两个基线各证明什么

| 基线 / base | 用在哪 / used by | 证明什么 / what it proves |
|---|---|---|
| `8c9f2ac` | `docs/前端UI架构/EXE-01-死样式截图回归/regression-summary.json` | **删掉的 CSS 真的是死的。** 把 `src/gateway/api/html.py` 渲染的服务端页面在改前改后各截一次（1440×900 与 390×844，共 12 张），把每个元素的全部 computed style 导出逐项比对。262 个元素、0 处差异 = 删除的样式类当时没有任何一个页面在用。 |
| `af20ae5` | `scripts/exe01/assert_scope.py`（EXE-01 窗口） | **改动没有越界。** 列出这一包动过的每个文件，逐个对照允许清单与红线清单。115 个文件全部落在 FE-00—FE-04 交付面内。 |

两者回答的是两个不同问题：一个是「**删对了吗**」（视觉/计算样式等价性），另一个是
「**只动了该动的吗**」（改动面）。用同一个基线并不会让任何一个更强。

---

## 二、为什么不是同一个 commit

`af20ae5` 是 `8c9f2ac` 的**直接下一个 commit**：

```
$ git log --oneline 8c9f2ac..af20ae5
af20ae5 docs: add COMM-01 frontend execution contract (AGENTS.md sec 14) + executor CLAUDE.md
```

截图回归是在 COMM-01 契约落盘**之前**跑的（那时最新提交就是 `8c9f2ac`），
scope 断言是在契约落盘**之后**写的（改动面要对照契约本身，所以基线取
`af20ae5`）。两个数字的差异纯粹是「两件事发生在同一天的先后两分钟」。

---

## 三、这个不一致有没有后果——可复算的证据

两个 commit 之间只改了两个文件，都是文档：

```
$ git diff --name-only 8c9f2ac af20ae5
AGENTS.md
CLAUDE.md
```

也就是说：

- **对截图回归**：`html.py`、样式表、模板在两个基线上逐字节相同，所以把基线换成
  `af20ae5` 重跑会得到同一批 sha256。用 `8c9f2ac` 不比用 `af20ae5` 宽松。
- **对 scope 断言**：`AGENTS.md` 和 `CLAUDE.md` 都不在 EXE-01 的改动面里
  （这一包一个字都没动它们），所以把基线换成 `8c9f2ac` 只会让被检文件从 115
  变成 117，多出来的两个仍然是「未改动」，判定不变。

**换句话说，两个基线对所有被证明的对象是同一个基线。** 按第三轮 Prompt 要求，
历史对照**不重跑**——重跑的输入与上次逐字节相同，输出必然相同，跑它只会产生
一份看起来很忙、实则没有新信息的产物。

---

## 四、EXE-01R 的第三个基线：`357d17c`

EXE-01R 又引入一个基线，这次是**故意的、且必须与前两个分开**：

| 基线 | 用在哪 | 为什么必须独立 |
|---|---|---|
| `357d17c` | `assert_scope.py`（EXE-01R 窗口）、`assert_function_budget.py` 的冻结豁免清单 | EXE-01R 的允许清单比 EXE-01 宽（多了 `.python-version`、`Makefile`、`ci.yml`、以及 `src/infrastructure/` 下**一个**精确文件）。如果两个包共用一个基线，EXE-01R 的这些放宽会**倒签**到 EXE-01 头上，等于事后给已交付的包补授权；反过来，监理在两包之间自己提交的 `docs/COMM-01-*` 修改会被算成本包越界。 |

所以 `assert_scope.py` 现在是**双窗口**：`af20ae5..3043217` 用 EXE-01 的清单，
`357d17c..HEAD` 用 EXE-01R 的清单，各自独立判定，任一窗口红即整体红。

---

## 五、复算方式

```bash
git log --oneline 8c9f2ac..af20ae5          # 应只有 1 个 commit
git diff --name-only 8c9f2ac af20ae5        # 应只有 AGENTS.md 与 CLAUDE.md
python3 scripts/exe01/assert_scope.py       # 应分别报出两个窗口各自 PASS
```
