# FE-00 · 12 个核心组件的视觉与交互合同

冻结的是**责任边界与交互规则**，不是像素。实现包（EXE-02—EXE-08）可以调整间距和字号，
但不得改变本文件规定的职责、主动作数量、空态与失败行为、以及禁止事项。

**通用规则**（12 个组件全部适用）

- 界面只出现大白话。`CreationProposalV1`、`InteractionResponseV1`、`basis_ref`
  这类内部合同名不得出现在普通用户可见文案里。
- 每个组件最多一个实心主动作（`.fe00-btn-solid`），其余为描边或纯文字动作。
- 触控目标 ≥ 44×44；正文 ≥ 14px，辅助文字 ≥ 12px，不得再出现 0.62rem 一类字号。
- 任何"不确定 / 待人工复核"的内容，视觉上**不得**使用确认绿。
- 组件内的设计 token 取 UserShell 作用域内的局部变量，不新增全局 `:root`。

---

## 1. StartAction · 起始入口

- **职责**：把"今天可以做什么"变成四个可点的动作，而不是一个空输入框。
- **视觉**：四张等宽卡；标题 + 一行说明；无图标堆砌。
- **交互**：点击后进入 `/content` 并把方向回填进输入区；**不**直接创建任务。
- **空态**：账号无任何资料时四个入口仍在，说明文案换成"先补什么"。
- **禁止**：不得因为没有历史就隐藏入口；不得造假数据填充。

## 2. OpportunityCard · 机会卡

- **职责**：给出 2—5 条"现在值得做"的具体选题，每条带理由。
- **视觉**：标题 + 理由一行 + 依据来源标签；难度以文字表述，不用星级。
- **交互**：主动作"用这条开始"——只回填输入区与方向，不建任务。
- **空态**：一条都没有时，显示为什么没有（资料缺口 / 刚建号），并给补资料入口。
- **禁止**：前端不得自行拼装依据；依据必须由服务端投影下发（EXE-03 依赖 EXE-02）。

## 3. AdvisorRecommendationCard · 推荐卡

- **职责**：参谋给出的一条建议方向。
- **视觉**：一句话结论在最上，展开后是理由与依据。
- **交互**：主动作"按这个继续"；次动作"换一个"。
- **失败**：模型未返回结构化内容时，降级为纯文本气泡，不显示半张卡。

## 4. AdvisorComparisonCard · 比较卡

- **职责**：把 2—3 个方向摆在一起比，帮用户裁决。
- **视觉**：等宽列；每列同样的比较维度，维度名在左侧固定。
- **交互**：每列一个"选这个"；不做打分排序，不替用户下结论。
- **禁止**：列数 > 3 时不得横向滚动堆叠，改为分组呈现。

## 5. AdvisorQuestionCard · 提问卡

- **职责**：参谋需要用户裁决时的**唯一**追问形态。
- **视觉**：问题一行 + 2—4 个候选答案 + 一个"跳过"。
- **交互**：至多一个可跳过的策略问题（COMM-01 B1 口径）；跳过不得阻断主链。
- **禁止**：不得连环追问；不得把追问做成必填表单。

## 6. CreationProposalCard · 创作方案卡

- **职责**：把"要做什么"完整摊开，让用户在制作前确认。
- **视觉**：分组呈现，每组可就地编辑；顶部显示"确认后才开始制作"。
- **交互**：主动作"确认并开始制作"；次动作"再聊聊"。
  真源版本变化导致确认失败时，提示重新编译方案，**不伪造已保存状态**。
- **界面用词**：叫"创作方案"，不叫 `CreationProposalV1`。

## 7. BrandBasisPanel · 品牌依据面板

- **职责**：常驻显示"这次用了哪些品牌依据"。
- **视觉**：常驻，**不折叠**；条目级列出，每条带来源类型徽标。
- **交互**：每条可反馈"这条不对"；反馈进队列，不直接改正式知识。
- **禁止**：不得显示 segment、digest、sha、prompt 等内部标识；
  `model_parametric` 条目须单独标注，且**不计入**品牌依据列表。

## 8. ProductionStep · 制作步骤

- **职责**：制作包里的一个可执行步骤。
- **视觉**：序号 + 动作 + 绑定的台词/字幕/资源条件 + 来源状态徽标。
- **交互**：步骤可折叠，但来源状态徽标在折叠态也必须可见。
- **禁止**：不得出现"镜头位置 N 承载原句"这类占位式假分镜。

## 9. ScriptBlock · 台词块

- **职责**：一段可直接念的台词。
- **视觉**：等宽正文，保留换行；每块标注用途与关联步骤。
- **交互**：整块可复制。
- **禁止**：台词块与字幕不得内容相同（v3 反模式，服务端机器判定）。

## 10. SubtitleCue · 字幕条

- **职责**：对应台词块的一条字幕。
- **视觉**：显示与所属 ScriptBlock 的对应关系。
- **约束**：必须是对应台词块的**连续原文片段**；长度、顺序、覆盖由服务端校验。
- **禁止**：不得由前端截断或改写生成。

## 11. SourceStatusBadge · 来源状态徽标

- **职责**：一眼看出这条信息可不可信。
- **四态与配色**：

  | 状态 | 含义 | 视觉 |
  |---|---|---|
  | `confirmed` | 已确认事实 | 确认绿 |
  | `compiler_derived` | 系统按规则推导 | 中性灰 |
  | `suggested_needs_review` | 建议，需人工复核 | 提示琥珀 |
  | `missing` | 缺资料 | 描边红 |

- **禁止**：`suggested_needs_review` **永远不得**映射成确认绿。
  无声音素材时 audio/editing 只能是 `compiler_derived` 或 `suggested_needs_review`。

## 12. DecisionActions · 决策操作区

- **职责**：采用 / 批准 / 导出 / 人工发布留痕。
- **视觉**：主动作一个（随角色变化：用户是"采用"，管理员是"批准"）；其余为次动作。
- **交互**：全部为追加式事件，服务端派生只读状态；撤回批准不产生新内容版本。
  `published_manual` 须先 `approved`。
- **禁止**：**没有自动发布入口**。导出可多次，计数定义为服务端完成导出准备。

---

## 主动作层级速查

| 阶段 | 实心主动作（唯一） | 次动作 |
|---|---|---|
| today | 四个起始入口中用户点的那一个 | 继续进行中的任务 |
| advisor | 「形成创作方案」 | 换方向 / 直接制作 |
| proposal | 「确认并开始制作」 | 再聊聊 / 就地编辑 |
| producing | 无（进行中） | 取消 |
| package | 「采用」（管理员：「批准」） | 修改 / 导出 / 人工发布留痕 |
