# FE-00 · 原型可用性走查材料与记录模板

> 本文件是**给主持人用的执行材料**。执行侧只交付材料；实际走查由 founder 组织。
> **当前状态：FE-00-HUMAN-WALKTHROUGH = BLOCKED_EXTERNAL（尚未执行）。**

## 一、用户来源与复用规则

- ≥5 名**非开发者**目标用户（品牌内容运营、门店内容负责人一类真实岗位）。
- 与 COMM-01 B6 可用性门**复用同一批人**（D-COMM-05b）；两轮记录分别留存，不合并。
- 走查前不做产品培训，不提前讲解界面。允许说明"这是纸面原型，点不动是正常的"。

## 二、主持人脚本

**开场（照读，30 秒）**

> 今天请你看的是一组还没做出来的界面草图。我们想知道你看到它会怎么想、想先点哪里。
> 没有标准答案，看不懂就是我们画得不好，不是你的问题。
> 请尽量把心里想的说出来——包括"这句什么意思"这种。

**过程纪律**

- 用户提问时**不要**直接回答"这个按钮是做什么的"，先反问"你觉得它会做什么"。
- 不引导、不提示、不替用户点。
- 用户卡住超过 60 秒，记为一次"卡顿"，然后才给最小提示并记下提示内容。
- 全程只记录，不辩解，不当场改设计。

## 三、五张任务卡

按顺序发放，每张单独计时。任务卡上只有这一句话，没有额外说明。

| # | 任务卡原文 | 观察什么 | 对应原型锚点 |
|---|---|---|---|
| 1 | 「你今天想发一条内容，从这个页面开始，你会先做什么？」 | 是否理解四个起始入口；是否被空输入框卡住 | 桌面 `#fe00-today` |
| 2 | 「你想讲讲你们店里不追着讲解这件事，请往下走到你觉得可以开始制作为止。」 | 是否理解"参谋"阶段；是否找到「形成创作方案」 | `#fe00-advisor` |
| 3 | 「这一屏在问你什么？你会点哪个？」 | 是否理解方案确认是"制作前最后一次改"；术语是否劝退 | `#fe00-proposal` |
| 4 | 「这份制作包里，哪些内容是可以直接用的，哪些还需要你自己确认？」 | 能否分辨四种来源状态；是否误把琥珀当绿灯 | `#fe00-package` |
| 5 | 「刚才那次失败了，你会怎么办？」 | 是否发现输入被保留；是否找到恢复动作 | `#fe00-failure` |

**追加观察（不单独计时）**：任务 2 中途请用户切换发布账号，观察是否预期"刚写的字会跟过去"。
这条直接对应 AdvisorDraftV1 的跨账号规则。

## 四、匿名记录模板

每位用户一份。**不记录姓名、手机号、所在门店等可识别信息**；只用编号。

```yaml
participant_id: U1            # U1..U5，与 B6 轮次保持同一编号
role: 品牌内容运营 | 门店内容负责人 | 其他（填写）
years_in_role:                # 整数
prior_product_exposure: 无 | 看过演示 | 用过旧版
session_date:                 # YYYY-MM-DD
facilitator:                  # 主持人编号，非姓名
prototype: 桌面 1440x900 | 移动 390x844

tasks:
  - id: 1
    completed: true | false | partial
    seconds:                  # 从发卡到用户说"好了"
    misclicks: 0              # 点了预期之外的元素的次数
    hesitations: 0            # 停顿 >10 秒的次数
    stuck: false              # 是否超过 60 秒需要提示
    hint_given: ""            # 给了什么提示，原话
    quotes:                   # 用户原话，逐字，不润色
      - ""
    gave_up: false
    give_up_reason: ""
  # 任务 2..5 同结构

cross_account_expectation: 跟过去 | 不跟过去 | 说不清
    # 用户对"切账号后草稿会怎样"的预期原话：
cross_account_quote: ""

source_status_reading:        # 任务 4：用户如何解读四种徽标
  confirmed: ""
  compiler_derived: ""
  suggested_needs_review: ""  # 关键：是否被当成"可以直接用"
  missing: ""

terminology_flags:            # 用户明确表示看不懂的词，逐字记录
  - ""

subjective:
  clarity_1_to_5:             # 「我清楚每一步在做什么」
  trust_1_to_5:               # 「我相信它给的依据是真的」
  would_use_1_to_5:           # 「我愿意用它做真实工作」
  one_sentence: ""            # 「用一句话说这个东西是干什么的」——用户原话

facilitator_notes: ""         # 只记事实，不写结论
```

## 五、汇总口径

走查结束后按下表汇总，作为 FE-00 放行凭据的一部分。

| 指标 | 口径 | 门槛 |
|---|---|---|
| 任务完成率 | `completed=true` 的任务数 ÷ 总任务数 | 记录即可，FE-00 不设硬阈值 |
| 卡顿率 | `stuck=true` 的任务数 ÷ 总任务数 | 记录 |
| 术语劝退 | `terminology_flags` 去重后的词表 | 出现的词必须逐条给出改法或保留理由 |
| **琥珀误读** | 把 `suggested_needs_review` 读成"可以直接用"的人数 | **≥1 人即须改视觉**，不得只改文案 |
| **跨账号预期** | `cross_account_expectation` 分布 | 记录；若多数人预期"跟过去"，须在界面上明说不跟 |

> B6 可用性门的七项 ≥80% 阈值属 EXE-09，**不适用于 FE-00**。
> FE-00 是设计冻结前的定性走查，产出是"改什么"，不是"过不过"。
