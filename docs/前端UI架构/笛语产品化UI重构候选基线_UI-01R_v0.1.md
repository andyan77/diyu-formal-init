## 1. 产品叙事

笛语不是一组功能入口，也不是把 Logo 零件依次拼起来的工具。当前候选叙事是：

> 一个还说不清的真实想法，被看见、理解、整理并找到方向，最后成为品牌能够自然使用的完整表达。

首页不解释能力清单。动画完成后只保留一句主张和一个进入动作。租户管理员与笛语运维不出现在公开首页，各自继续使用独立地址。

## 2. 产品空间

| 产品空间 | 用户在这里完成什么 | 主要对象 | 不应成为首屏内容 |
|---|---|---|---|
| 公开与认证 | 认识笛语并进入自己的工作空间 | 首页、登录、激活 | 入口架构、权限字段、工程说明 |
| 内容工作空间 | 从自然想法得到内容，继续修改与承接系列 | 对话、当前成品、历史、系列、私人素材 | 编译轨迹、内部产品门、整套配置表 |
| 陈列工作空间 | 从商品与现场条件得到可执行参考方案并局部调整 | 挂杆、商品组、空间关系、执行顺序 | 内容工作台三栏、确认/审批流程 |
| 品牌管理 | 维护品牌、账号、成员、商品与演示体验 | 品牌表达、账号定位、负责团队、商品 | 入驻教程、完成项说明卡、验收证据 |
| 笛语运维 | 查看租户服务关系并处理需求反馈 | 租户、服务状态、反馈 | 裸数据库字段、全量内部日志 |

五个空间是信息架构，不是五套应用、权限体系或状态机。

## 3. 四条任务旅程

### 3.1 进入工作

公开首页 → 租户用户登录 → 用户首页 → 选择内容或陈列。

品牌管理员和笛语运维从各自独立登录地址进入对应首页。激活流程设置密码后直接进入其目标空间，不停在成功提示。

### 3.2 内容协作

自然输入 → 按需展开创作方向 → 得到完整成品 → 用自然语言说明修改意图 → 新版本成为当前版 → 历史版本仍可打开。

桌面是“对话 / 成品”双工作面；移动只保留这两个视图切换。当前版默认可读，历史按数量折叠。

### 3.3 陈列参考

商品与现场条件 → 空间关系图 → 执行顺序 → 选择一个局部调整 → 图和顺序同步变化 → 新方案成为当前版。

页面先让用户看到“挂哪里、先做什么、哪里可调”，再提供一句自然边界。

### 3.4 品牌管理

品牌概览 → 只突出一个当前缺口 → 查看品牌表达/账号定位 → 查看两类账号的内容演示。

已完成资料压成可读对象，不用四张同款卡片重复宣告就绪。

## 4. 页面层级

UI-01R 只重做六张决定方向的 HTML：

1. 公开首页：叙事动效定格后，一句主张和一个动作；
2. 登录：一个共享视觉骨架，由入口上下文决定名称和后续落点；
3. 内容工作空间：用户首页与内容工作台是同一空间内的两个状态；
4. 陈列参考方案：空间图为主，执行顺序和局部调整为辅；
5. 品牌管理概览：品牌表达、唯一就绪缺口、账号和演示关系；
6. 笛语运维首页：优先待办、服务状态、租户与需求反馈。

旧 UI-01 的 19 张页面不是最终页面数量合同。UI-02 应按旅程判断哪些能力成为页面、状态、标签、抽屉或弹窗。

## 5. 产品语言

产品主页面只使用用户完成任务所需的业务语言。完整映射见
[笛语产品语言词典 V1](笛语产品语言词典_V1.md)。

共同规则：

- 先说用户在哪里、当前重要状态和下一步；
- 帮助只在字段附近出现，并回答“这里怎么填”；
- 已完成事项只保留对象名称与当前状态；
- 真正影响当前动作的边界压成一句；
- 不在普通页面讲述工程过程、内部审查或软件如何证明自己。

## 6. 视觉语法

- 品牌层：正式 VI、呼吸白、墨黑与极少朱砂，标题可带宋体气质；
- 任务层：无衬线正文、足够对比度、明确状态和 44px 触控目标；
- 内容：对话产生变化，成品承担阅读中心；
- 陈列：空间、挂位、密度与顺序承担视觉中心；
- 品牌管理：对象关系和缺口承担视觉中心；
- 运维：优先级、服务与租户关系承担视觉中心；
- 一个页面最多一个实心朱砂主按钮；
- 不以卡片包裹每段说明，不让空白变成无内容的大面积空洞。

桌面基准为 `1440×900`，移动基准为 `390×844`。主内容宽度约 `1180—1240px`，所有页面不得横向溢出。

## 7. 首页叙事动效

三个 6—8 秒候选均为“状态转化”，不是 Logo 零件展示：

- A：表达种子 → 犹疑与分叉 → 方向 → 退去多余路径 → 完整表达；
- B：两段表达 → 看见距离 → 留白形成关系 → 完整表达；
- C：拥挤片段 → 编辑选择 → 去除竞争 → 清楚焦点。

执行侧推荐 A，因为它的主体、阻力、转折、结果和产品价值联系最完整。所有候选静默、只播一次、可跳过/重播；减少动效时直接显示正式 Logo；最终帧直接消费正式 SVG。

## 8. 评审与产品分离

`review/index.html` 是唯一评审工具，承载目录、前后页、桌面/移动画布、流程/自由模式、身份入口和新窗口打开。`product/*.html` 不出现页码、评审目录、候选说明或“返回评审”。

静态产品流程必须有真实落点：登录进入工作空间，激活进入对应入口，自然修改形成新的当前版本与历史记录，陈列调整直接改变方案图。提示可以说明结果，但不能代替结果。

## 9. 资产能力总账在界面中的位置

[能力资产台账](../能力资产台账/README.md)服务于产品和工程决策，不是普通用户页面。候选登记、运行激活、单次调用、已验证能力与真实采用必须分开理解。台账 CSV/Markdown 是 JSON/JSONL 真源的只读投影，不成为新的编辑入口。

内容方向面板只展示精简集合，并允许每轴不选；全量目录、缺口状态和资产 ID 不进入普通创作页面。

## 10. 创始人最终裁决与后继

1. 首页正式方向采用 A“种子找到声音”；B/C 继续保留为历史候选；
2. A 进入 UI-02 后减少路径演示感，朱砂只承担一次关键方向转折，正式 Logo 至少保留一次
   约 `0.8—1s` 的静止呼吸；减少动效时直接显示正式 Logo 和首页；
3. 正式 VI SVG 是唯一 Logo 真源，不重画 Logo；
4. 首页当前文字仍是产品候选，不冻结为永久品牌口号；
5. 六张代表页只验证方向，不是正式 React 逐页复制模板；
6. UI-02 将信息架构进一步收敛为租户管理端、统一创作端、笛语运维端三套工程空间，并以
   四条完整旅程重新判断页面、状态、标签和抽屉；
7. UI-02 的 DM01 只交付完整文字参考方案，UI-01R 历史页中的图形化空间表达不进入首期承诺。

UI-01R 据此正式 `CLOSED`。UI-03 才承接正式 React 产品骨架与内容主链且不切换生产默认 UI；
UI-04 才承接剩余首期业务、生产替换和回退。
