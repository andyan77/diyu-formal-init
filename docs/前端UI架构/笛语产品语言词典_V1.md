# 笛语产品语言词典 V1

用途：让页面用用户正在做的事说话。它是 UI 文案候选的共同词典，不改变后台对象、权限或接口命名。

| 内部概念 | 用户实际看到 | 使用场景 | 字段附近的帮助说明 |
|---|---|---|---|
| tenant user entry | 登录笛语 | 租户用户认证页 | 继续内容与陈列工作 |
| tenant admin | 品牌管理员 / 品牌管理 | 管理入口和页面标题 | 管理成员、发布账号与品牌资料 |
| ops operator | 笛语运维 | 独立运维入口 | 查看租户运行与需求反馈 |
| tenant onboarding / readiness | 品牌资料 | 品牌管理导航 | 只突出现在确实缺少的资料 |
| brand profile | 品牌表达 | 品牌概览与维护 | 品牌长期坚持怎样看、怎样说 |
| five-part expression profile | 账号画像 | 发布账号详情 | 这个账号从什么位置、对谁、长期讲什么 |
| control organization | 负责团队 | 账号列表 | 哪个团队负责维护这个账号 |
| operator | 成员 / 使用者 | 账号成员列表 | 谁可以用这个账号工作 |
| publishing account | 发布账号 | 创作身份栏、管理列表 | 当前内容以哪个账号的身份表达 |
| platform carrier | 可用平台 / 内容形式 | 发布账号详情与创作顶部 | 同一发布账号获准面向哪些平台、做成什么形式 |
| content role | 表达身份摘要 | 账号画像与创作顶部 | 总部、区域或门店从哪里观察和回应 |
| brand product | 商品资料 | 品牌管理与本次任务 | 只写现在能确认的商品事实 |

## 2. 动作语言

| 内部动作 | 用户动作 | 出现场景 |
|---|---|---|
| generate | 开始创作 / 做成内容 | 输入区主动作 |
| recompile | 另做平台版本 | 当前成品的次级操作 |
| reuse version | 从这个版本继续 | 历史版本 |
| export artifact | 导出当前版本 | 成品操作 |
| create publishing account | 创建发布账号 | 品牌管理抽屉 |
| assign operator | 添加成员 | 账号成员区 |
| create platform carrier | 添加可用平台 | 发布账号详情 |
| update expression profile | 调整账号画像 | 账号详情 |
| local display revision | 调整这一处 | 陈列方案 |
| feedback classify | 分类并回复 | 运维需求队列 |

## 3. 状态语言

| 内部状态 | 用户实际看到 | 说明 |
|---|---|---|
| ready | 已可开始创作 / 工作空间已就绪 | 只在确实可以开始时使用 |
| missing input | 还差… | 直接说缺的业务资料和补齐动作 |
| current version | 当前版本 · Vn | 默认展示 |
| superseded version | 历史版本 | 不使用“失效任务”一类技术词 |
| recoverable error | 这次没有完成，可以再试一次 | 同时给返回或重试动作 |
| forbidden entry | 当前账号不能进入这里 | 给返回对应入口或退出重登 |
| processing | 正在整理… | 只描述用户正在等待的结果 |
| success | 已保存 / 新版本已生成 | 必须同时让结果在页面中可见 |

## 4. 不进入主页面的表达

以下内容可以存在于工程文档、运行留痕或受控运维证据中，但不复制到普通产品页面：

- 里程碑编号、架构决策编号和产品门编号；
- 行级隔离、原子性、模型供应商、数据库版本、部署提交、内部 schema；
- 测试通过、审查结论、冻结证据、验收索引、候选状态；
- 生成输入、规则字段、资产 ID、内部媒体合同和权限术语；
- “不会自动更新某对象”的重复免责声明。

若一条边界真实影响当前动作，应翻译成一句自然提示，例如：

- 商品字段旁：“只写现在能确认的事实，其他以后需要时再补。”
- 陈列方案旁：“这是陈列参考，请按现场尺寸和商品状态调整。”
- 生成内容旁：“使用前请按实际情况确认。”

## 5. 页面文案检查

1. 首屏是否回答“我在哪里、现在最重要的状态、下一步是什么”；
2. 每段说明是否真的改变当前动作；不能就删除或下沉；
3. 成功提示是否伴随可见结果，而不是只有短暂消息；
4. 同一个对象是否始终使用同一个用户名称；
5. 帮助是否贴着字段，并且只解释当前怎么填；
6. 是否误把内部证明过程写成用户需要阅读的内容。

| 旧表述或内部对象 | UI-05 用户实际看到 | 使用位置与边界 |
|---|---|---|
| 平台载体被列成发布账号 | 可用平台 / 内容形式 | 平台是同一发布账号下的任务目标，不另造账号或人设 |
| `platform carrier` → “平台版本” | 平台与形式 | 只有从现有成品另做其他平台内容时，结果才叫“平台版本” |
| 五段画像 / 账号定位 / 表达边界并列 | 账号画像 | 五段合为一份版本化画像；“能代表什么、不能代表什么”承接原表达边界 |
| ContentRole / 内容位置 | 表达身份摘要 | 主页面只给一句人话摘要；内部稳定分类不作为第二套人设表单 |
| 物理内容账号行数 | 发布账号数 / 可用平台数 | 两个统计分开，不把一个根账号和三个平台误写成四个账号 |
| 生产就绪 / 知识完整度 | 当前可用与待补 | 只用“可用 / 有条件可用 / 暂不可用”，并同时说明依据、缺口、影响和补充入口 |
| 模型用量 | 已记录模型用量 | 只代表系统收到的调用记录，不冒充供应商账单或完整成本 |
| quota | 本月租户内容额度 | 必须紧邻周期和租户方案来源，不把它写成供应商账单、费用或企业服务承诺 |
| 管理员账号 / 双入口资格 | 品牌管理员 / 租户用户 | 首期入口职责互斥；管理员只做品牌管理，租户用户按资格做内容或陈列 |
| 固定人物关系风格（如“闺蜜聊天”） | 本次人物关系与边界 | 人物关系由自然语言保留，不进入风格封闭枚举；可追问当前表达者或讲法 |
| 全品牌 / 总部内容组 / 演示内容 | 品牌全员 / 总部专用 / 指定区域 | 资料卡和导入统一使用三级可用范围；指定区域必须选择具体区域 |
| 品牌资料库中的发布账号与画像 | 发布账号 / 账号画像 | 只在发布账号页面维护；品牌资料库不重复保存账号画像 |
| 任意输入即生成 | 自然交流 / 继续补充 / 正在整理 | 普通交流不生成；信息不足只追问一次，要求足够后直接生成 |
| 内部生成失败原因 | 这次还没能整理成一份可靠的成品 | 保留对话和输入，只提供“继续补充”“再试一次” |
| streaming / run state | 正在整理 / 正在生成 / 正在核对 / 正在完成 | 只显示可信过程，不展示模型原始输出、内部修复或未完成正文 |
