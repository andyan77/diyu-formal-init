Gate A 一次关闭正式入驻、身份、逻辑发布账号与多平台关系：

```text
登录身份（真实自然人）

  → 一个或多个逻辑发布账号
```

使用资格、五段画像维护资格和账号控制组织必须相互独立。

### 正式合同与生命周期

- `CreatePublishingAccountRequest` 和 `CreatePlatformCarrierRequest` 继续使用
  `extra="forbid"`；正式 React 不再发送 `target`。抖音、小红书、微信视频号由一个
  类型安全穷举映射产生，`微信视频号` 不再经过中文字符串删词。
- 一个逻辑发布账号只有一套 `ContentRole`、控制组织和当前五段画像；小红书图文／视频等
  内容目标只作为该账号的平台形式投影，不复制账号或画像。
- 全新租户先读取确定性品牌表达草案，经管理员修订和确认后才能创建发布账号。账号创建页
  同时给出基于租户、品牌边界和通用企业账号冷启动规则的五段画像候选；候选可编辑，保存后
  才形成 V1，不冒充品牌事实。
- 账号使用资格与五段画像维护资格按账号分别保存。创建账号不再静默授予维护权；成员工作
  资格调整在未显式提交维护清单时保持旧维护资格，专用维护接口只改变一个账号的维护资格。
  租户管理员入口、账号控制组织和两类资格互不推导。
- 成员支持名称／所属组织修改、停用、恢复、工作资格与重设链接；逻辑账号支持名称／控制
  组织、画像历史和新版本、停用／恢复；平台目标支持添加、停用和恢复。停用只阻止新选择，
  不删除历史任务、系列或版本引用。迁移 `20260807_34` 只增添
  `content_accounts.platform_enabled`，为 expand-first。
- `/user` 展示自然人和所属组织；`/content` 从当前发布账号读取控制组织、
  `ContentRole` 和画像版本。切换平台或形式不会改变自然人、逻辑账号、控制组织或画像。
