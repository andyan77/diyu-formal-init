## 一、唯一用户结果

只完成：

> 笛语服饰一个门店 × 一组双层墙面挂杆 × 一次任务库存输入
> → 确定性文字**参考执行方案** V1
> → 用户自然提出实际差异时，只修订受影响部分形成 V2，并保留 V1。

系统只交付参考建议，不自动执行陈列，也不承担监管责任。没有修改意见时停在 V1 即为正常
完成；真实现场采用与效果不是 M7-1 的软件验收条件。

## 二、固定边界

- 不调用 DeepSeek；
- 不消费 P1—P5、发布账号或 `ContentRole`；
- 不接 ERP/POS，不核验库存；
- 不识图、不评分、不巡检、不下整改任务；
- 不扩展橱窗、中岛、入口、模特、全店空间或其他陈列场景；
- 不建设通用陈列优化器、LLM 陈列路径、审批状态机或第二编译器。

租户、品牌、门店、执行组织和登录操作人必须来自可信服务端作用域。账号与数据访问权限是
**一次性的系统资格**，不是每次生成任务的授权流程。任务库存只在本次任务内成立；方案是
参考建议，不表示总部批准、系统核验或门店已经执行。

## 三、产品语义裁决（2026-07-25，取代原确认流程）

用户裁定：系统根据租户、品牌、账号、用户输入和可用知识交付最佳参考建议。因此：

- 不需要用户授权系统“给建议”；
- 不需要确认人、确认日期、系统代录人、复核人；
- 不设“业务指定／系统建议”二选一；
- 不要求用户实际执行后回复，才承认 V1 成立；
- 后台自动记录真实登录操作者、作用域、输入、版本和时间，但不展示成用户任务负担。

被撤销的表述（原写在本文件、`MILESTONE.md`、候选资料和项目记忆中）：**阿丹已现场确认、
现场差异为无、商品当前在店且可售、`2026-07-25` 为现场确认日期、`007+006` 与 `005` 已被
确认为业务指定、`confirmed_by` / `confirmed_at` / `system_submitted_by` 等业务确认语义。**
它们没有可靠用户来源，不得继续作为真实事实引用；原 V1 保留为历史开发证据，但不再称为
“阿丹现场确认后的真实门店方案”。

## 四、当前输入口径

- 当前资料统一定义为：**用户提供的本次任务快照，用于生成参考方案；其中现场条件和库存
  仍未证明为真实现场事实。**
- `007+006` 是系统根据本次资料形成的主焦点建议，`005` 是较弱回应建议；只有用户在自然
  输入中明确写出“必须、固定、不可改变”等表达时，才在本次任务内成为硬要求。
- 门店固定结构（上下杆、容量、正挂位、黄金视线、来客方向、硬限制）与本次任务数据
  （主题、密度、焦点建议、商品轻量属性、数量）分开保存；本次库存不写成长期真实库存，
  本次焦点建议不写成长期品牌政策。
- 不再用旧库存快照做 `enforce_exact` 比对阻止新任务：新的自然输入即是本次真源。
- 生产 `dm01-rule-compiler-v1` 保持同一确定性执行器和上下/左右/焦点/库存守恒合同；
  真实路径不查询 `ZX-*`，`ZX-*` 只保留在合成回归夹具中。

## 五、缺口处理与版本规则

1. 信息足够时直接生成；
2. 非关键缺失（缺主题、缺焦点建议商品、个别商品没有陈列属性资料）通过收窄方案处理，
   并在正文说明；
3. 只有缺少无法替代的 SKU 或数量、导致方案无法成立时，才允许**一次合并的最小追问**；
   追问不得涉及确认人、授权或责任归属；
4. V1 是正常完整成果；没有修改意见时停在 V1 即为正常完成；
5. 用户自然提出实际差异或修改要求时，才生成局部 V2 并保留 V1；“现场无差异”只保留 V1，
   不为状态流转强造 V2。
